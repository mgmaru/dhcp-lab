## 質問

> scpとは何か？`cp` は同じマシンの中で使うコマンドだと覚えている。scpは、ネットワークを介してファイルを転送するようなコマンドなのか？

---

## 結論

**はい、そのとおりです。**

**scp**（**S**ecure **C**o**p**y）は、**SSHの仕組みを使って、ネットワーク越しにファイルをコピーする**コマンドです。

| コマンド | コピーする範囲 | 例えると |
|---|---|---|
| `cp` | 同じマシンの中だけ | 机の上で、書類を別の引き出しに移す |
| `scp` | **別のマシンとの間**（ネットワーク越し） | 書類を書留郵便で、別の建物に送る |

```text
【cp】同じマシンの中
 ┌──────────── マシンA ────────────┐
 │  ~/a.txt  ──コピー──▶  ~/backup/ │
 └─────────────────────────────────┘

【scp】別のマシンへ
 ┌──── マシンA ────┐                   ┌──── マシンB ────┐
 │  ~/a.txt        │ ──SSH（暗号化）──▶ │  ~/backup/      │
 └─────────────────┘    ネットワーク     └─────────────────┘
```

---

## scpの特徴

### 1. SSHと同じ通信路を使う

| 項目 | 内容 |
|---|---|
| 使うポート | SSHと同じ **22番（TCP）** |
| 暗号化 | **される**（途中で盗み見られても中身はわからない） |
| ログイン方法 | SSHと同じ（パスワードか鍵） |

**SSHでログインできる相手なら、scpも使える**と考えてよいです。

### 2. 書き方は `cp` とほぼ同じ

`cp コピー元 コピー先` と同じ順番で書きます。違うのは、別のマシンのファイルを `ユーザー名@ホスト:パス` の形で書くことだけです。

```bash
cp  ~/a.txt  ~/backup/a.txt                    # 同じマシンの中でコピー
scp ~/a.txt  kajih@10.0.0.10:~/backup/a.txt    # 10.0.0.10 へコピー
```

---

## 書き方

### 基本の形

```text
scp  [オプション]  コピー元  コピー先
```

### `:` が付いている側が別のマシン

```text
scp  ~/debs/*.deb    kajih@10.0.0.10:~/debs/
     └─ コピー元 ─┘   └──────── コピー先 ────────┘
     自分のマシン       ユーザー名 @ ホスト : パス
                       └─ kajih ┘ └10.0.0.10┘ └~/debs/┘
```

| 部分 | 意味 |
|---|---|
| `kajih` | 相手のマシンでログインするユーザー名 |
| `@` | ユーザー名とホストの区切り |
| `10.0.0.10` | 相手のマシン（IPアドレスか、`~/.ssh/config` に書いたホスト名） |
| `:` | ホストとパスの区切り。**これがあると「別のマシンのファイル」という意味になる** |
| `~/debs/` | 相手のマシンの中のパス |

> ユーザー名を省略すると、今ログインしているユーザーと同じ名前でログインしようとします。

## コピーの向きは3パターン

[client-vm-offline-package-install.md](client-vm-offline-package-install.md) の「5-2」に書いたコピー方法①〜③は、それぞれ次のパターンに当たります。

### ① 取ってくる（ダウンロード）

**Client VMで実行**します。Router VMのファイルを、自分（Client VM）に取ってきます。

```bash
scp kajih@10.0.0.1:~/debs/*.deb ~/debs/
```

```text
 Router VM ──────── ファイル ────────▶ Client VM
 (10.0.0.1)                           （ここで実行）
```

### ② 送る（アップロード）

**Router VMで実行**します。自分（Router VM）のファイルを、Client VMに送ります。

```bash
scp ~/debs/*.deb kajih@10.0.0.10:~/debs/
```

```text
 Router VM ──────── ファイル ────────▶ Client VM
 （ここで実行）                        (10.0.0.10)
```

### ③ 別のマシン同士でコピーする（手元のPCで中継）

**手元のPCで実行**します。Router VMのファイルを、手元のPCを経由してClient VMに送ります。

```bash
scp -3 -o ProxyJump=router router:~/debs/*.deb kajih@10.0.0.10:~/debs/
```

```text
 Router VM ──ファイル──▶ 手元のPC ──ファイル──▶ Client VM
                        （ここで実行・中継）
```

> `-3` を付けると、ファイルが手元のPCを経由します。Router VMとClient VMが**直接SSHで認証し合わなくて済む**ので、手元のPCの鍵でしかVMにログインできないときに便利です。

### 3パターンの比較

| パターン | 実行する場所 | コピー元 | コピー先 | `:` が付く側 |
|---|---|---|---|---|
| ① 取ってくる | Client VM | 別のマシン（Router VM） | 自分 | コピー元 |
| ② 送る | Router VM | 自分 | 別のマシン（Client VM） | コピー先 |
| ③ 中継する | 手元のPC | 別のマシン（Router VM） | 別のマシン（Client VM） | 両方 |

## よく使うオプション

| オプション | 意味 | 例 |
|---|---|---|
| `-r` | フォルダごとコピーする（`cp -r` と同じ） | `scp -r ~/debs kajih@10.0.0.10:~/` |
| `-P ポート` | SSHが22番以外のポートで待っているとき（**大文字のP**） | `scp -P 2222 a.txt kajih@host:~/` |
| `-J 踏み台` | 踏み台を経由する（`ssh -J` と同じ） | `scp -J router a.txt kajih@10.0.0.10:~/` |
| `-3` | 別のマシン同士のコピーを、手元のPCで中継する | 上の③ |
| `-p` | 更新日時などを保ったままコピーする（**小文字のp**） | `scp -p a.txt kajih@host:~/` |

> **`-P` と `-p` に注意**
>
> | コマンド | ポートの指定 |
> |---|---|
> | `ssh` | 小文字の `-p` |
> | `scp` | **大文字の `-P`** |
>
> `scp` の小文字の `-p` は「更新日時などを保つ」という別のオプションです。間違えやすいので気をつけてください。

## 似たコマンドとの比較

| コマンド | 特徴 | 向いている場面 |
|---|---|---|
| `cp` | 同じマシンの中でコピーする | ローカルの作業 |
| `scp` | SSH越しに1回コピーする。書き方が簡単 | 数個のファイルをさっと送る（今回のような場面） |
| `sftp` | SSH越しに、対話しながら操作する（`ls`、`get`、`put` など） | 相手のフォルダを見ながら、選んで送受信する |
| `rsync` | 差分だけを送る。途中で止まっても続きから再開できる | 大量のファイルや、何度も同期する場面 |

> 補足：新しいOpenSSH（バージョン9.0以降）の `scp` は、内部では `sftp` と同じ仕組み（SFTPプロトコル）で転送しています。使い方は変わらないので、意識しなくて大丈夫です。

## 今回の場面でscpを使う理由

```text
 Internet
    │ ① apt download
    ▼
 Router VM ──② scp（SSH、22番、VMnet2経由）──▶ Client VM ──③ apt install
```

| 理由 | 説明 |
|---|---|
| SSHがすでに通っている | Router VMとClient VMの間は、SSHでつながることを確認済み（[ssh-via-vmnet2-qa.md](ssh-via-vmnet2-qa.md) の `$SSH_CONNECTION` の結果） |
| 追加の準備がいらない | SSHが通るならscpも通る。新しいソフトや設定は不要 |
| インターネットは不要 | Client VMはインターネットに出られないが、コピーは**VMnet2の中**で完結する |

## つまずきやすいポイント

| 症状 | 原因と対処 |
|---|---|
| ファイルが `kajih@10.0.0.10` という名前で、**自分のマシンに**できてしまった | `:` を付け忘れている。`kajih@10.0.0.10:~/debs/` のように、ホストの後ろに `:` が必要 |
| `Permission denied (publickey)` と表示される | 相手のマシンにログインできていない。まず `ssh kajih@10.0.0.10` でログインできるか確かめる。鍵が手元のPCにしかない場合は、パターン③（`-3`）を使う |
| `No such file or directory` と表示される | コピー先のフォルダが相手のマシンにない。先に `ssh kajih@10.0.0.10 'mkdir -p ~/debs'` で作る |
| フォルダをコピーしたら `not a regular file` と表示される | `-r` を付け忘れている |
| `-p 2222` でポートを指定したのにつながらない | `scp` のポート指定は**大文字の `-P`** |

---

## まとめ

- **scp**は、**SSHの仕組みを使って、ネットワーク越しにファイルをコピーする**コマンド
- SSHと同じ**22番ポート**を使い、通信は**暗号化**される。**SSHでログインできる相手なら、scpも使える**
- 書き方は `cp` とほぼ同じ。別のマシンのファイルは `ユーザー名@ホスト:パス` と書く。**`:` があるかどうか**が大事
- コピーの向きは「取ってくる」「送る」「手元のPCで中継する（`-3`）」の3パターン
- ポートの指定は、`ssh` が小文字の `-p`、`scp` が**大文字の `-P`**
- 今回は、Router VMとClient VMの間でSSHが通っているので、scpでパッケージのファイルを渡せる

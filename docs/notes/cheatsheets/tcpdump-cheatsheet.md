# tcpdump 早見表

tcpdumpでよく使うオプションとフィルタを、すぐに引けるようにまとめた早見表です。

- 基本の形：`sudo tcpdump [オプション] '[フィルタ]'`
- キャプチャ（ネットワークから読む）には `sudo` が必要です。ファイルを読む（`-r`）だけなら不要です。
- 詳しい使い方や、つまずいたときの対処は、関連ドキュメントを参照してください。

関連ドキュメント：

## 1. この演習でまず使うもの

迷ったら、まずこの表から選んでください。

| やりたいこと | コマンド |
|---|---|
| 画面で観察する | `sudo tcpdump -i <LAN_IF> -n 'udp port 9067 or udp port 9068'` |
| 中身（16進数と文字）も見る | `sudo tcpdump -i <LAN_IF> -n -X 'udp port 9067 or udp port 9068'` |
| MACアドレスも見る | `sudo tcpdump -i <LAN_IF> -n -e 'udp port 9067 or udp port 9068'` |
| 画面に表示しながらファイルに保存する | `sudo tcpdump -i <LAN_IF> -n -U --print -w /tmp/captures/step1.pcap 'udp port 9067 or udp port 9068'` |
| 保存したファイルを読む | `tcpdump -n -r /tmp/captures/step1.pcap` |
| DHCPを観察する（STEP 2以降） | `sudo tcpdump -i <LAN_IF> -n -e -v 'udp port 67 or udp port 68'` |

> `<LAN_IF>` は、VMnet2側のNICの名前（例：`ens34`）に読み替えます。`ip -br addr` で確認できます。

## 2. オプション一覧

### 2-1. どこをキャプチャするか

| オプション | 意味 | 例 |
|---|---|---|
| `-i <NIC名>` | キャプチャするNICを指定する | `-i ens34` |
| `-i any` | すべてのNICをまとめてキャプチャする（宛先MACアドレスなど、Ethernetの情報の一部が表示されない） | `-i any` |
| `-D` | キャプチャできるNICの一覧を表示する | `sudo tcpdump -D` |
| `-p` | 自分宛て以外のパケットを受け取らない（プロミスキャスモードにしない） | `-p` |
| `-Q in` / `-Q out` | 受信したパケットだけ／送信したパケットだけを表示する | `-Q in` |

### 2-2. 表示の仕方

| オプション | 意味 | 使いどころ |
|---|---|---|
| `-n` | IPアドレスやポート番号を**名前に変換せず、数字のまま**表示する | **ほぼ毎回付ける**。名前の変換で表示が遅くなるのも防げる |
| `-e` | **MACアドレス**（Ethernetの情報）も表示する | ブロードキャスト（`ff:ff:ff:ff:ff:ff`）の確認、DHCPのClientの特定 |
| `-X` | パケットの中身を**16進数と文字**で表示する（Ethernetヘッダを除く） | 送ったデータが入っているか確認する |
| `-XX` | `-X` に加えて、Ethernetヘッダも表示する | MACアドレス部分のバイトも見たいとき |
| `-A` | パケットの中身を**文字だけ**で表示する | テキストのデータを読みたいとき |
| `-v` | 詳しく表示する（TTL、IPのID、チェックサムなど） | DHCPのメッセージの中身を見る（`-v` で DHCPのオプションも表示される） |
| `-vv` / `-vvv` | さらに詳しく表示する | `-v` で足りないとき |
| `-q` | 簡単に表示する（プロトコルの詳細を省く） | 流れだけ見たいとき |
| `-l` | 1行ずつすぐに出力する | `\| tee` や `\| grep` に渡すとき |

### 2-3. 時刻の表示

| オプション | 表示 | 例 |
|---|---|---|
| （指定なし） | 時:分:秒.マイクロ秒 | `16:29:22.747236` |
| `-t` | 時刻を表示しない | — |
| `-tttt` | 日付付きで表示する | `2026-10-15 16:29:22.747236` |
| `-ttt` | 1つ前のパケットからの経過時間 | `00:00:18.115566` |

### 2-4. 量を制限する

| オプション | 意味 | 例 |
|---|---|---|
| `-c <数>` | 指定した数のパケットを受け取ったら、自動で終了する | `-c 10` |
| `-s <バイト数>` | 1パケットあたり、先頭から何バイトまで保存するか（標準は262144バイト＝ほぼ全部） | `-s 128` |

### 2-5. ファイルへの保存と読み込み

| オプション | 意味 | 注意点 |
|---|---|---|
| `-w <ファイル>` | パケットを**pcap形式で保存**する。画面には表示しない | ホームディレクトリに直接保存すると `Permission denied` になることがある |
| `-r <ファイル>` | 保存したファイルから**読む** | `sudo` は不要 |
| `--print` | `-w` で保存しながら、画面にも表示する | tcpdump 4.99で使える |
| `-U` | パケットを受け取るたびに、すぐファイルに書き込む | 付けないと、止めるまでファイルが空のことがある |
| `-Z <ユーザー>` | キャプチャの準備が終わったら、指定したユーザーに切り替える | `-Z $USER` でホームディレクトリに保存できる |
| `-C <MB>` | ファイルが指定サイズを超えたら、新しいファイルに切り替える | 長時間キャプチャするとき |
| `-G <秒>` | 指定した秒数ごとに、新しいファイルに切り替える | ファイル名に `%H%M%S` などの時刻を入れて使う |

> 詳しくは [tcpdump-save-capture.md](../runbooks/tcpdump-save-capture.md) を参照してください。

## 3. フィルタ一覧

フィルタは、コマンドの最後に書きます。`'` で囲むのがおすすめです（`(` や `)` をシェルに解釈させないため）。

### 3-1. 基本のフィルタ

| フィルタ | 意味 | 例 |
|---|---|---|
| `udp` / `tcp` / `icmp` / `arp` | プロトコルで絞る | `'udp'` |
| `host <IP>` | 送信元か宛先が、そのIP | `'host 10.0.0.10'` |
| `src host <IP>` | 送信元が、そのIP | `'src host 10.0.0.10'` |
| `dst host <IP>` | 宛先が、そのIP | `'dst host 255.255.255.255'` |
| `net <ネットワーク>` | そのネットワークのIP | `'net 10.0.0.0/24'` |
| `port <番号>` | 送信元か宛先が、そのポート | `'port 9067'` |
| `src port <番号>` | 送信元ポートが、その番号 | `'src port 9068'` |
| `dst port <番号>` | 宛先ポートが、その番号 | `'dst port 67'` |
| `portrange <開始>-<終了>` | ポート番号の範囲 | `'portrange 9067-9068'` |
| `ether host <MAC>` | 送信元か宛先が、そのMACアドレス | `'ether host 00:0c:29:20:6c:ff'` |
| `broadcast` | Ethernetのブロードキャスト（宛先MACが `ff:ff:ff:ff:ff:ff`） | `'broadcast'` |

### 3-2. 組み合わせ

| 書き方 | 意味 | 例 |
|---|---|---|
| `and` | 両方に当てはまる | `'udp and port 9067'` |
| `or` | どちらかに当てはまる | `'udp port 9067 or udp port 9068'` |
| `not` | 当てはまらない | `'not port 22'` |
| `( )` | まとめる | `'udp and (port 67 or port 68)'` |

> tcpdumpのフィルタでは、`and` と `or` は**同じ優先順位**で、左から順に計算されます。`and` と `or` を混ぜるときは、`( )` で囲んで意味をはっきりさせてください。

### 3-3. この演習でよく使うフィルタ

| 見たいもの | フィルタ |
|---|---|
| STEP 1の通信 | `'udp port 9067 or udp port 9068'` |
| DHCP（STEP 2以降） | `'udp port 67 or udp port 68'` |
| 特定のClientのDHCPだけ | `'(udp port 67 or udp port 68) and ether host <ClientのMAC>'` |
| ブロードキャストだけ | `'broadcast'` |
| ARP（IPアドレスからMACアドレスを調べる通信） | `'arp'` |
| SSHの通信を除いて全部 | `'not port 22'` |

> SSHでVMに入ってtcpdumpを使うとき、フィルタを付けないと、**自分のSSHの通信**が大量に表示されます。`'not port 22'` で除くか、見たいポートで絞ってください。

## 4. 目的別のコマンド例

| 目的 | コマンド |
|---|---|
| 使えるNICを確認する | `sudo tcpdump -D` |
| 何でもいいので10個だけ見る | `sudo tcpdump -i <LAN_IF> -n -c 10` |
| SSH以外を全部見る | `sudo tcpdump -i <LAN_IF> -n 'not port 22'` |
| 送信元ポートを確認する | `sudo tcpdump -i <LAN_IF> -n 'udp port 9067'` |
| ブロードキャストかどうかを確認する | `sudo tcpdump -i <LAN_IF> -n -e 'udp port 9067'` |
| データの中身を確認する | `sudo tcpdump -i <LAN_IF> -n -X 'udp port 9067'` |
| 受信したパケットだけ見る | `sudo tcpdump -i <LAN_IF> -n -Q in 'udp port 9067'` |
| 日付付きでテキストに保存する | `sudo tcpdump -i <LAN_IF> -n -tttt -l 'udp port 9067' \| tee /tmp/captures/log.txt` |
| ホームディレクトリにpcapで保存する | `sudo tcpdump -Z $USER -i <LAN_IF> -n -U --print -w ~/step1.pcap 'udp port 9067 or udp port 9068'` |
| 保存したファイルを、条件を変えて読み直す | `tcpdump -n -e -X -r ~/step1.pcap 'udp dst port 9067'` |
| DHCPのメッセージを詳しく見る | `sudo tcpdump -i <LAN_IF> -n -e -vv 'udp port 67 or udp port 68'` |

## 5. 出力の読み方

### `-n` だけの場合

```text
16:29:22.747236 IP 10.0.0.10.9068 > 255.255.255.255.9067: UDP, length 15
└──── 時刻 ────┘   └── 送信元 ──┘   └──── 宛先 ────┘  └── UDPのデータ長 ──┘
                   IP.ポート          IP.ポート
```

### `-n -e` の場合（MACアドレス付き）

```text
16:29:22.747236 00:0c:29:20:6c:ff > ff:ff:ff:ff:ff:ff, ethertype IPv4 (0x0800), length 60: 10.0.0.10.9068 > 255.255.255.255.9067: UDP, length 15
                └── 送信元MAC ──┘   └── 宛先MAC ──┘   └── 中身の種類 ──┘       └フレーム長┘
```

| 表示 | 意味 |
|---|---|
| `10.0.0.10.9068` | IPアドレス `10.0.0.10` の、ポート `9068`（最後の `.` の後ろがポート番号） |
| `>` | 左から右へ送られた |
| `ff:ff:ff:ff:ff:ff` | 宛先MACがブロードキャスト |
| `length 60`（`:` より前） | Ethernetフレーム全体の長さ |
| `length 15`（最後） | UDPのデータの長さ |

> 実際の出力の詳しい読み方は [step1-results.md](../results/step1-results.md) を参照してください。

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `You don't have permission to capture on that device` | `sudo` を付け忘れている |
| 何も表示されない | `-i` のNICが違う（`-D` や `ip -br addr` で確認）／フィルタのポート番号が違う／tcpdumpより先に通信を送ってしまった |
| SSHのパケットが大量に流れる | フィルタで絞る（`'not port 22'` など） |
| ポート番号が `bootps` のような名前で表示される | `-n` を付ける |
| `-w` を付けたら、画面に何も表示されない | 普通の動き。表示もしたいときは `--print` を付ける |
| `-w` で保存すると `Permission denied` | ホームディレクトリに直接保存しようとしている。`/tmp` に保存するか、`-Z $USER` を付ける |
| `-r` で読むと `truncated dump file ... only got 0` | ファイルが空。tcpdumpを `Ctrl + C` で止めてから読む。次からは `-U` を付ける |
| `\| tee` に渡すと表示が遅れる | `-l` を付ける |
| `-i any` で宛先MACアドレスが表示されない | `-i any` ではEthernetの情報の一部が取れない。NIC名を指定する |
| フィルタに `(` を書いたらシェルのエラーになる | フィルタ全体を `'` で囲む |

> 詳しい対処は [tcpdump-save-capture.md のトラブルシューティング](../runbooks/tcpdump-save-capture.md#5-トラブルシューティング) を参照してください。

## 結論

ユニキャスト・ブロードキャスト・マルチキャストは、**1つのパケットを誰に届けるか**による呼び分けです。

| 種類 | 宛先 | 例えると | IPv4の宛先アドレスの例 |
|---|---|---|---|
| **ユニキャスト** | **1台**だけ | 手紙：宛名の1人に届く | `10.0.0.1` |
| **ブロードキャスト** | 同じネットワークの**全員** | 校内放送：全員に聞こえる | `255.255.255.255`、`10.0.0.255` |
| **マルチキャスト** | **参加を申し込んだグループ**だけ | メーリングリスト：登録した人だけに届く | `224.0.0.0`〜`239.255.255.255` |

## 図で見る違い

```text
【ユニキャスト】宛先：10.0.0.1
  送信者 ──────────▶ ホストA  ✅ 受け取る
                     ホストB  （届かない）
                     ホストC  （届かない）

【ブロードキャスト】宛先：255.255.255.255
  送信者 ─────┬────▶ ホストA  ✅ 受け取る
              ├────▶ ホストB  ✅ 受け取る
              └────▶ ホストC  ✅ 受け取る

【マルチキャスト】宛先：224.0.0.251（グループ）
  送信者 ─────┬────▶ ホストA  ✅ グループに参加している
              │      ホストB  （参加していない → 受け取らない）
              └────▶ ホストC  ✅ グループに参加している
```

## ユニキャスト

**1対1**の通信です。一番普通の通信で、ほとんどの通信がユニキャストです。

- 例：Web閲覧、SSH、`ping 10.0.0.1`
- TCPもUDPも使える
- ルーターを越えて、別のネットワークにも届く
- 手順書の「2. ユニキャストで送り合う（nc）」がユニキャスト

```text
 Client (10.0.0.10) ──────── 宛先 10.0.0.1 ────────▶ Server (10.0.0.1)
```

---

## ブロードキャスト

同じネットワークの**全員**に届く通信です。

### いつ使うか

相手のアドレスがわからないときに、「誰か○○を持っていますか？」と全員に聞くために使います。

- 例1：**DHCPDISCOVER**：「誰かDHCPサーバーはいますか？」
- 例2：**ARP**：「10.0.0.1のMACアドレスを持っているのは誰ですか？」
- 手順書の「3. ブロードキャストで送る（socat）」がブロードキャスト

### ブロードキャストの宛先アドレス

| 宛先 | 呼び方 | 意味 |
|---|---|---|
| `255.255.255.255` | リミテッドブロードキャスト | 自分がつながっているネットワーク全体。**自分のIPを知らなくても使える**（DHCPで使う） |
| `10.0.0.255` | ディレクテッドブロードキャスト | `10.0.0.0/24` というネットワーク全体（サブネット宛て） |

### 注意点

- **ルーターを越えない**
  - 届く範囲は同じネットワーク（ブロードキャストドメイン）の中だけ
  - DHCPサーバーが別のネットワークにあるときは、**リレーエージェント**が中継する

```text
 ┌──── ネットワークA ────┐          ┌──── ネットワークB ────┐
 │ Client ── 全員宛て ──▶ │ ルーター │                      │
 │ ホストX ✅ 受け取る    │   ✖     │ ホストY （届かない）  │
 └──────────────────────┘ 越えない └──────────────────────┘
```

- **関係ないホストにも負担がかかる**
  - 全員が受け取り、OSが中身を確認して、不要なら捨てる
  - 台数が多いネットワークでブロードキャストが多いと、みんなの負担になる
- **UDPでしか使えない**
  - TCPは1対1の接続なので、全員宛てには送れない
- **送るにはソケットの設定が必要**
  - ソケットで `SO_BROADCAST` を有効にしないと、送信がエラーになる（手順書の3-3で確認）

## マルチキャスト

**参加を申し込んだグループ**にだけ届く通信です。

### しくみ

```text
 ① ホストAとCが「224.0.0.251のグループに参加します」と申し込む（IGMPというプロトコルを使う）
 ② 送信者が 224.0.0.251 宛てに1回送る
 ③ 参加しているホストAとCだけが受け取る
```

### いつ使うか

同じデータを、欲しい人たちにまとめて送りたいときに使います。

| 用途 | マルチキャストアドレス |
|---|---|
| mDNS（`○○.local` という名前を調べる） | `224.0.0.251` |
| OSPF（ルーター同士で経路情報を交換する） | `224.0.0.5` |
| 動画・IPテレビの配信 | `239.x.x.x` など |

### ほかの方法と比べたよさ

| 方法 | 10台に同じデータを送るとき |
|---|---|
| ユニキャスト | 10回送る必要がある（送信者とネットワークの負担が大きい） |
| ブロードキャスト | 1回で済むが、**欲しくない人にも届く** |
| **マルチキャスト** | 1回で済み、**欲しい人にだけ届く** |

### 注意点

- **UDPでしか使えない**
- `224.0.0.x` は同じネットワークの中だけで使うアドレスで、ルーターを越えない
- それ以外のアドレスでルーターを越えるには、ルーター側の設定が必要

## 比較表

| 観点 | ユニキャスト | ブロードキャスト | マルチキャスト |
|---|---|---|---|
| 宛先 | 1台 | 全員 | 参加したグループ |
| 関係ないホストへの影響 | なし | **あり**（全員が受け取る） | ほぼなし |
| ルーターを越えるか | 越える | **越えない** | 設定しだい（`224.0.0.x` は越えない） |
| TCPで使えるか | 使える | 使えない | 使えない |
| 宛先MACアドレス | 相手のMAC | `ff:ff:ff:ff:ff:ff` | `01:00:5e:` で始まるMAC |
| IPv6にあるか | ある | **ない** | ある |
| 身近な例 | Web、SSH | DHCPDISCOVER、ARP | mDNS、OSPF |

## DHCPとの関係

### DHCP（IPv4）

場面によって使い分けています。

| 場面 | 使う通信 | 理由 |
|---|---|---|
| DISCOVER（サーバーを探す） | ブロードキャスト | ClientにIPがなく、サーバーのアドレスも知らない |
| OFFER / ACK（サーバーの返事） | ブロードキャストかユニキャスト | ClientにまだIPがないので、ブロードキャストで返すことがある |
| REQUEST（最初の申し込み） | ブロードキャスト | 複数のサーバーに「このサーバーの提案を選んだ」と伝えるため |
| RENEW（リースの更新） | ユニキャスト | すでにIPがあり、サーバーのアドレスも知っている |
| リレーエージェント ⇔ サーバー | ユニキャスト | ルーターを越えるため |

### DHCPv6（IPv6）

IPv6には**ブロードキャストがありません**。代わりに、マルチキャストアドレス `ff02::1:2`（全DHCPサーバー・リレーエージェントのグループ）宛てに送ります。

```text
 IPv4：Client ── 255.255.255.255 宛て（ブロードキャスト）──▶ 全員
 IPv6：Client ── ff02::1:2 宛て（マルチキャスト）──────────▶ DHCPサーバーのグループだけ
```

## tcpdumpで見分ける

### 宛先IPアドレスで見分ける

```text
IP 10.0.0.10.9068 > 10.0.0.1.9067: UDP ...          ← ユニキャスト
IP 10.0.0.10.9068 > 255.255.255.255.9067: UDP ...   ← ブロードキャスト
IP 10.0.0.10.5353 > 224.0.0.251.5353: UDP ...       ← マルチキャスト（mDNS）
```

### 宛先MACアドレスで見分ける

`-e` オプションを付けると、MACアドレスも表示されます。

```bash
sudo tcpdump -i <LAN_IF> -n -e 'udp port 9067 or udp port 9068'
```

| 宛先MACアドレス | 種類 |
|---|---|
| 相手のNICのMAC（例：`00:0c:29:xx:xx:xx`） | ユニキャスト |
| `ff:ff:ff:ff:ff:ff` | ブロードキャスト |
| `01:00:5e:` で始まる | マルチキャスト |

> 手順書の手順2（nc）と手順3（socat）を `-e` 付きで実行すると、ユニキャストとブロードキャストで宛先MACが変わる様子を確認できます。

## まとめ

- **ユニキャスト**：1台に届ける。一番普通の通信
- **ブロードキャスト**：同じネットワークの全員に届ける。相手がわからないときに使う。ルーターは越えない
- **マルチキャスト**：参加したグループにだけ届ける。同じデータを効率よく配れる
- ブロードキャストとマルチキャストは**UDPでしか使えない**
- DHCP（IPv4）は、最初はClientにIPがないので**ブロードキャスト**を使う。DHCPv6はIPv6にブロードキャストがないので**マルチキャスト**を使う

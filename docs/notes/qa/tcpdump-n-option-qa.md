# Q&A：tcpdumpの `-n` オプションとは何か

[tcpdump-cheatsheet.md](../cheatsheets/tcpdump-cheatsheet.md) を読んで出た質問と、その回答をまとめたメモです。

> **このドキュメントで一番大事なこと**
>
> `-n` を付けないと、tcpdumpは**IPアドレスをホスト名に、ポート番号をサービス名に置き換えて**表示します（例：`68` → `bootpc`）。
>
> 置き換わるのは**画面の表示だけ**で、パケットの中身はいつも数字です。この演習では、**`-n` を付けて数字のまま見る**のがおすすめです。

## 質問

> `-n` のオプションがよくわからない。
>
> IPアドレスやポート番号を名前に変換しないと、どのような表示になるのか？

---

## 1. 結論：数字の代わりに名前で表示される

tcpdumpは、`-n` を付けないと、パケットの中の**数字を、人間が読みやすい名前に置き換えて**表示しようとします。

| 置き換えるもの | 置き換え先 | 例 |
|---|---|---|
| IPアドレス | **ホスト名** | `10.0.0.1` → `debian-router` |
| ポート番号 | **サービス名** | `67` → `bootps`、`68` → `bootpc`、`22` → `ssh` |

`-n` は、「**この置き換えをしないで、数字のまま表示して**」というオプションです。

```text
                 パケットの中身（いつも数字）
                 10.0.0.10 / 68
                        │
          ┌─────────────┴─────────────┐
          ▼                           ▼
    -n なし                      -n あり
    名前を調べて置き換える          そのまま表示する
    10.0.0.10.bootpc             10.0.0.10.68
```

> **置き換わるのは画面の表示だけ**です。パケットに「bootpc」という文字が入っているわけではありません。パケットの中身は、いつも数字（IPアドレスとポート番号）です。

---

## 2. 表示の比較

### 2-1. DHCP（STEP 2以降で見る通信）

```text
-n なし: IP 0.0.0.0.bootpc > 255.255.255.255.bootps: BOOTP/DHCP, Request ...
-n あり: IP 0.0.0.0.68     > 255.255.255.255.67:     BOOTP/DHCP, Request ...
```

| 数字 | 名前 | 名前の意味 |
|---|---|---|
| 67 | `bootps` | **BOOTP S**erver（BOOTPのサーバー） |
| 68 | `bootpc` | **BOOTP C**lient（BOOTPのクライアント） |

DHCPは、**BOOTP**という古いプロトコルを元に作られています。そのため、67番と68番は、DHCPではなくBOOTPの名前で登録されています。

`-n` を付けないと、「DHCPなのにbootpって何？」と、慣れないうちは混乱しやすくなります。

### 2-2. SSH

```text
-n なし: IP 10.0.0.1.40166 > 10.0.0.10.ssh: Flags [P.], ...
-n あり: IP 10.0.0.1.40166 > 10.0.0.10.22:  Flags [P.], ...
```

| 数字 | `-n` なしの表示 | 理由 |
|---|---|---|
| 22 | `ssh` | SSHのポートとして登録されている |
| 40166 | `40166`（数字のまま） | エフェメラルポートなので、名前が登録されていない |

### 2-3. STEP 1の通信

```text
-n なし: IP 10.0.0.10.9068 > 10.0.0.1.9067: UDP, length 6
-n あり: IP 10.0.0.10.9068 > 10.0.0.1.9067: UDP, length 6
```

9067番と9068番は登録されていないので、**どちらでも数字のまま**です。IPアドレスも、今の環境では名前が見つからないので、数字のまま表示されるはずです。

### 2-4. よく見るポートの名前

| 数字 | 名前 | 何のサービスか |
|---|---|---|
| 22 | `ssh` | SSH |
| 53 | `domain` | DNS（名前解決） |
| 67 | `bootps` | DHCP（BOOTP）のサーバー |
| 68 | `bootpc` | DHCP（BOOTP）のクライアント |
| 80 | `http` | Web（暗号化なし） |
| 123 | `ntp` | 時刻合わせ |
| 443 | `https` | Web（暗号化あり） |

> DNSが `dns` ではなく `domain` と表示されるなど、**名前から中身を想像しにくいもの**もあります。

## 3. 名前はどこから来るのか

| 置き換えるもの | 調べる場所 | 説明 |
|---|---|---|
| ポート番号 → サービス名 | `/etc/services` | ポート番号とサービス名の対応表。OSに最初から入っている |
| IPアドレス → ホスト名 | `/etc/hosts` | 自分で書くIPアドレスとホスト名の対応表 |
| | DNS（逆引き） | `/etc/hosts` になければ、DNSサーバーに「このIPアドレスの名前は？」と問い合わせる |

```text
 tcpdump（-n なし）
   │
   ├─ ポート 68 の名前は？ ──▶ /etc/services ──▶ 「bootpc」
   │
   └─ IP 10.0.0.1 の名前は？
          ├─▶ /etc/hosts に書いてあれば、その名前
          └─▶ なければ DNS に問い合わせる ──▶ 見つからなければ数字のまま
```

> 例えば `/etc/hosts` に `10.0.0.1 debian-router` という行を書くと、`-n` なしのときは `10.0.0.1.9067` が `debian-router.9067` と表示されます。

## 4. なぜ `-n` を付けるのがおすすめなのか

| 理由 | 説明 |
|---|---|
| **パケットの本当の値が見える** | `bootpc` ではなく `68` と表示されるので、自分で書くコードの数字（`bind(0.0.0.0, 68)` など）と、そのまま見比べられる |
| **表示が遅くならない** | `-n` なしでは、IPアドレスごとにDNSへ問い合わせる。**Client VMはDNSに届かない**ので、問い合わせが失敗するまで待たされ、表示が止まったように見えることがある |
| **余計なパケットが増えない** | 名前を調べるためのDNSの問い合わせ自体がパケットとして流れ、キャプチャに混ざることがある |
| **名前が正しいとは限らない** | ポートの名前は「普通はこのサービスが使う」という目安にすぎない。例えば、67番で別のプログラムを動かしても、表示は `bootps` になる |

```text
 -n なしで、DNSに届かない Client VM で実行すると……

 パケットが届く ──▶ 「10.0.0.1 の名前は？」と DNS に問い合わせ ──▶ 返事が来ない……（待つ）
                                                                    │
                                              数秒〜数十秒後、あきらめて数字で表示 ◀┘
```

## 5. 「数字のほうがわかりやすい」という感想について

> 個人的には数字のほうがわかりやすい気がする。変換したほうがわかりづらいような気がした。

**その感覚は正しいです。** 特にこの演習では、数字で見るほうが向いています。

| 場面 | 数字（`-n` あり）が向いている理由 |
|---|---|
| DHCPを実装する | コードに書くのは `67`・`68` という数字。`bootps`・`bootpc` と表示されると、頭の中で変換し直す必要がある |
| 演習で独自のポートを使う | 9067番・9068番は名前がないので、どちらにしても数字で表示される。数字に統一したほうが読みやすい |
| 問題を調べる | 「名前が正しいとは限らない」ので、本当の値（数字）を見るほうが確実 |

一方で、名前の表示が役立つ場面もあります。

| 場面 | 名前（`-n` なし）が役立つ理由 |
|---|---|
| 知らないネットワークの通信をざっと眺める | `https`、`domain`、`ssh` のように、何の通信かがひと目でわかる |
| ポート番号を覚えていない | 番号を調べなくても、だいたいのサービスがわかる |

**おすすめ**：普段は `-n` を付けて数字で見ます。ポート番号の意味がわからないときだけ、`/etc/services` で調べます（[6章](#6-自分で確かめる方法)）。

> よく使うポート（22、53、67、68、80、443）は、演習を進めるうちに自然に覚えられます。覚えてしまえば、数字のほうが速く読めます。

## 6. 自分で確かめる方法

### 6-1. 同じファイルを、`-n` あり・なしで読み比べる

```bash
tcpdump -r step1.pcap      # -n なし
tcpdump -n -r step1.pcap   # -n あり
```

STEP 1のファイルでは、どちらも同じ表示になるはずです（9067番・9068番には名前がないため）。

### 6-2. ポート番号の名前を調べる

```bash
grep -w -E '22/tcp|67/udp|68/udp' /etc/services
```

出力例：

```text
ssh             22/tcp
bootps          67/udp
bootpc          68/udp
```

名前から番号を調べることもできます。

```bash
getent services bootpc
```

```text
bootpc                68/udp
```

### 6-3. 9067番には名前がないことを確認する

```bash
grep -w 9067 /etc/services
```

何も表示されなければ、名前は登録されていません。

### 6-4. IPアドレスの名前を調べる

```bash
getent hosts 10.0.0.1
```

何も表示されなければ、`/etc/hosts` にもDNSにも名前がないので、`-n` なしでも数字で表示されます。

---

## 7. まとめ

- `-n` なし：IPアドレスを**ホスト名**に、ポート番号を**サービス名**に置き換えて表示する
  - 例：`68` → `bootpc`、`67` → `bootps`、`22` → `ssh`、`53` → `domain`
- `-n` あり：パケットに入っている**数字のまま**表示する
- 置き換わるのは**表示だけ**。パケットの中身はいつも数字
- 名前は、ポートなら `/etc/services`、IPアドレスなら `/etc/hosts` やDNSから調べている
- **`-n` を付ける理由**：本当の値が見える、表示が遅くならない、余計なパケットが増えない、名前が正しいとは限らない
- 「数字のほうがわかりやすい」という感覚は正しい。DHCPを実装するこの演習では、**数字で見るのが向いている**

# Q&A：メモリとスライスの基礎（1マスと箱、型の大きさ、`append` で容量が増えるしくみ）

[go-buffer-size-and-append-qa.md](go-buffer-size-and-append-qa.md) で「`append` は容量を先に確保したほうがよい」と話したあとに出た質問と、その回答をまとめたメモです。**メモリとスライスの、いちばん基礎的なところ**を扱います。

> **このドキュメントで一番大事なこと**
>
> - メモリの最小の単位は **1バイト（1マス）**。マスごとに**番地**が付いている
> - スライスの**箱1個**（要素1個）の大きさは、**型によって変わる**。`[]byte` なら1バイト、`[]int` なら（64ビットのマシンで）**8バイト**
> - 長さと容量は、**バイト数ではなく、箱（要素）の数**で数える
> - `append` で容量が足りなくなると、**直前の容量をもとに**新しい容量が決まる。**小さいうちは2倍**、大きくなると**1.25倍に近づく**
> - 容量の増え方は**ランダムではなく、計算で決まる**。入れる数が分かっているなら、最初から容量を確保すると、**引っ越しも余りも出ない**

## 質問

> **Q1.** `append` する前提の処理なら、容量を確保しないと、余分に容量を確保してしまうということか？ 最初の容量の倍で増えていく、という認識でよいか？
>
> **Q2.** 「`[]int` に1000個を1個ずつ append した」とあるが、`int` は1個4バイトだから、4個の箱単位にした、という認識でよいか？
>
> **Q3.** 「最後に余る空きの箱」で、なぜ280個の空きができたのか？ これはランダムか？
>
> **Q4.** メモリの箱1個は、8バイトなのか？

---

## 1. 結論

| 質問 | 答え |
|---|---|
| Q1. 余分に確保するか？ 最初の容量の倍で増えるか？ | **余分は出る**（引っ越しで捨てられる古い箱と、最後に余る空き）。増え方の基準は「最初の容量」ではなく「**直前の容量**」で、倍になるのは**小さいうちだけ**（[5章](#5-append-で容量はどう増えるか)・[7章](#7-容量を確保しないときの余分)） |
| Q2. `int` は4バイトだから4個単位？ | **いいえ。** この Mac では `int` は **8バイト**。最初の容量が4個なのは、Go が**最初に32バイト**確保するから（32 ÷ 8 ＝ 4）（[3章](#3-型によって箱1個の大きさが違う)・[4章](#4-最初の容量は32バイト分)） |
| Q3. 280個の空きはランダム？ | **ランダムではない。** 容量の増え方は計算で決まる。1000個入れると、毎回必ず容量1280になり、280個余る（[6章](#6-最後に余る空きの数はどう決まるか)） |
| Q4. メモリの箱1個は8バイト？ | **いいえ。** メモリの最小の単位は **1バイト（1マス）**。「箱」はスライスの**要素1個**のことで、`[]int` の箱1個が、メモリの8マスを使っている（[2章](#2-メモリの1マスとスライスの箱)） |

> 確かめた環境：Mac（Apple シリコン、64ビット）、Go 1.26.4。

## 2. メモリの1マスと、スライスの箱

### 2-1. 2つを区別する

これまでのノートで「箱」と言っていたのは、**スライスの要素1個**のことです。メモリそのものの単位とは、別のものです。

| 言葉 | 大きさ | 説明 |
|---|---|---|
| **メモリの1マス** | **いつも1バイト** | メモリは、1バイトごとに**番地**が付いている。これが本当の最小の単位 |
| **スライスの箱**（要素1個） | **型によって変わる** | `[]byte` なら1バイト（1マス）、`[]int` なら8バイト（8マス） |

### 2-2. 図で見る

```text
 メモリ（1マス ＝ 1バイト。マスごとに番地が付いている）

 番地  100 101 102 103 104 105 106 107 108 109 110 111 112 113 114 115 116 …
      ┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
      │   │   │   │   │   │   │   │   │   │   │   │   │   │   │   │   │   │
      └───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘


 []byte の場合：箱1個 ＝ 1マス

      ┌───┬───┬───┐
      │ 0 │ 1 │ 2 │ …     ← 要素の番号
      └───┴───┴───┘
      100 101 102          箱の番地は、1ずつ進む


 []int の場合：箱1個 ＝ 8マス

      ┌───────────────────────────────┬───────────────────────────────┬───
      │              0                │              1                │ 2 …
      └───────────────────────────────┴───────────────────────────────┴───
      100                             108                             116
                                       箱の番地は、8ずつ進む
```

Mac で、となりの要素との番地の差を測りました。

| 型 | となりの要素との番地の差 | つまり |
|---|---|---|
| `[]byte` | **1** | 1バイトずつ並んでいる |
| `[]int` | **8** | 8バイトずつ並んでいる |

### 2-3. 長さと容量は「箱の数」で数える

長さと容量は、**メモリのマスの数ではなく、スライスの箱（要素）の数**で数えます。

| 書き方 | 長さ・容量 | メモリのマス（バイト）にすると |
|---|---|---|
| `make([]byte, 4)` | 4個 | 4バイト |
| `make([]int, 4)` | 4個 | **32バイト**（4個 × 8バイト） |

```text
 make([]int, 4)

 スライスの箱で数えると：4個
 ┌───────────┬───────────┬───────────┬───────────┐
 │     0     │     1     │     2     │     3     │   長さ 4、容量 4
 └───────────┴───────────┴───────────┴───────────┘

 メモリのマスで数えると：32マス（32バイト）
 ┌┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┐
 └┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┘
```

> これまでのノートの図（`buf` の番地100、101、102…）は、どれも `[]byte` の例でした。`[]byte` では「メモリの1マス」と「スライスの箱1個」が同じ大きさなので、区別しなくても困りませんでした。`[]int` の話になって、初めて違いが出てきます。

## 3. 型によって、箱1個の大きさが違う

### 3-1. `int` の大きさは、マシンによって変わる

| マシン | `int` の大きさ |
|---|---|
| **64ビット**のマシン（今の Mac、VM の Linux など） | **8バイト** |
| 32ビットのマシン（古いパソコンなど） | 4バイト |

Mac で確かめると、`int` は **8バイト**でした。

名前に数字が付いた型は、**どのマシンでも大きさが決まっています**。

| 型 | 大きさ |
|---|---|
| `byte`（`uint8` と同じ） | 1バイト |
| `int16`、`uint16` | 2バイト |
| `int32`、`uint32` | 4バイト |
| `int64`、`uint64` | 8バイト |
| `int`、`uint` | マシンによる（64ビットなら8バイト） |

> 数字は「**ビット数**」です。8ビット ＝ 1バイトなので、`int32` は 32 ÷ 8 ＝ 4バイト、`int64` は 64 ÷ 8 ＝ 8バイトです。

### 3-2. DHCP とのつながり

DHCP のメッセージは、「ここから4バイトが IPアドレス」「ここから2バイトがフラグ」のように、**バイト数がきっちり決まっています**。そのため、DHCP を作るときは、マシンによって大きさが変わる `int` ではなく、**大きさの決まった型**（`uint8`、`uint16`、`uint32`）や、`[]byte` を使うことになります。

## 4. 最初の容量は「32バイト分」

### 4-1. 型ごとの、最初の容量

空のスライスに最初の1個を `append` したとき、型ごとの容量を確かめました。

| 型 | 1個の大きさ | 最初の容量 | メモリにすると |
|---|---|---|---|
| `[]byte` | 1バイト | **32個** | 32バイト |
| `[]int32` | 4バイト | **8個** | 32バイト |
| `[]int` | 8バイト | **4個** | 32バイト |
| `[][16]byte` | 16バイト | **2個** | 32バイト |

**どの型でも、メモリにすると32バイト**です。Go は、小さいスライスを作るとき、**最低でも32バイト**確保します。その32バイトに入る数が、最初の容量になります。

```text
 最初に確保される 32バイト（32マス）

 ┌┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┐
 └┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┘

 []byte  なら  1マスずつ区切る → 箱 32個
 ┌┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┐
 └┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┘

 []int32 なら  4マスずつ区切る → 箱 8個
 ┌───┬───┬───┬───┬───┬───┬───┬───┐
 └───┴───┴───┴───┴───┴───┴───┴───┘

 []int   なら  8マスずつ区切る → 箱 4個
 ┌───────┬───────┬───────┬───────┐
 └───────┴───────┴───────┴───────┘
```

### 4-2. Q2 への答え

「`int` は4バイトだから、4個の箱単位にした」のではありません。

```text
 ✗ int が 4バイト だから、4個単位
 ✓ int が 8バイト で、最初に 32バイト 確保するから、32 ÷ 8 ＝ 4個
```

> 最初に確保される量の細かいルールは、Go のバージョンによって変わることがあります。

## 5. `append` で、容量はどう増えるか

### 5-1. 基準は「直前の容量」

容量が足りなくなって引っ越すとき、新しい容量は、**引っ越す直前の容量**をもとに決まります。

```text
 ✗「最初の容量の倍」     4 → 8 → 8 → 8 …     （いつも 4 × 2 ではない）
 ✓「直前の容量をもとに」 4 → 8 → 16 → 32 …    （毎回、そのときの容量から次を決める）
```

先に容量を確保していても、それを超えると、**そこから**また増えていきます。

| 始め方 | 101個目を入れたあとの容量 |
|---|---|
| `make([]int, 0, 100)` | **224**（100 をもとに、約2倍） |

### 5-2. 倍になるのは、小さいうちだけ

`[]int` で2万個まで入れて、1回の引っ越しで何倍になったかを見ました。

| 容量の変わり方 | 何倍になったか |
|---|---|
| 4 → 8 → 16 → 32 → 64 → 128 → 256 → 512 | **2.00倍**（ずっと倍） |
| 512 → 848 | 1.66倍 |
| 848 → 1280 | 1.51倍 |
| 1280 → 1792 | 1.40倍 |
| 2560 → 3408 | 1.33倍 |
| 9216 → 12288 | 1.33倍 |
| 16384 → 21504 | 1.31倍 |

```text
 1回の引っ越しで、何倍になるか

 2.0 ┤■■■■■■■■
     │        ■
 1.5 ┤         ■ ■   ■
     │            ■ ■ ■ ■ ■ ■
 1.25┤ ‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥‥  ← 大きくなると、ここに近づいていく
     └─┬───────┬───┬───────────────▶ 容量
       4      512 848            21504
       └ 2倍 ──┘└ だんだんゆるやかに ─┘
```

大きいスライスで毎回2倍にすると、**余る箱が大きくなりすぎる**からです。容量が1万のときに2倍にすると、1万個分が一度に余ってしまいます。

### 5-3. 計算のしかた

容量が256以上のとき、Go 1.26 では、次のように計算されています。

```text
 ① 新しい容量 ＝ 直前の容量 ＋（直前の容量 ＋ 768）÷ 4
 ② それを、メモリの区切りの大きさまで切り上げる
```

①の式は、**小さいうちはほぼ2倍、大きくなるほど1.25倍に近づく**ように作られています。

```text
 直前の容量が小さいとき（例：256）
   256 ＋（256 ＋ 768）÷ 4 ＝ 256 ＋ 256 ＝ 512    → ちょうど 2倍

 直前の容量が大きいとき（例：100000）
   100000 ＋（100000 ＋ 768）÷ 4 ≒ 100000 ＋ 25192 → 約 1.25倍
   （768 の影響が小さくなり、「＋ 直前の容量 ÷ 4」＝ 1.25倍 に近づく）
```

### 5-4. きれいな倍数にならない理由：メモリの区切り

②の「メモリの区切り」は、Go がメモリを確保するときに使う、**決まった大きさのいくつかの区切り**です。計算した大きさを、**それ以上で一番小さい区切り**まで切り上げます（[go-buffer-size-and-append-qa.md の 3-1](go-buffer-size-and-append-qa.md#3-1-容量を指定しても確保される量は減らない) で、1000バイトが1024バイトになったのと同じ理由）。

```text
 []int で、512 から引っ越すとき

 ① 512 ＋（512 ＋ 768）÷ 4 ＝ 832個
 ② 832個 × 8バイト ＝ 6656バイト
    → 区切りの 6784バイト に切り上げ
    → 6784 ÷ 8 ＝ 848個           ← これが実際の容量

 []int で、848 から引っ越すとき

 ① 848 ＋（848 ＋ 768）÷ 4 ＝ 1252個
 ② 1252個 × 8バイト ＝ 10016バイト
    → 区切りの 10240バイト に切り上げ
    → 10240 ÷ 8 ＝ 1280個         ← これが実際の容量
```

切り上げは**バイト数**で行われるので、**型によって容量の増え方が違って見えます**。

| 型 | 512 から引っ越したあとの容量 | 計算 |
|---|---|---|
| `[]int`（8バイト） | **848** | 832個 × 8 ＝ 6656バイト → 6784バイト → 848個 |
| `[]byte`（1バイト） | **896** | 832個 × 1 ＝ 832バイト → 896バイト → 896個 |

> 計算式やメモリの区切りの大きさは、**Go のバージョンで変わることがあります**。覚える必要はありません。「**小さいうちは2倍、大きくなるとゆるやかに。直前の容量が基準。最後にメモリの区切りに切り上げる**」と覚えておけば十分です。

## 6. 最後に余る空きの数は、どう決まるか

### 6-1. ランダムではない

同じプログラムを3回動かしても、`[]int` に1000個入れたあとの容量は、**3回とも1280**でした。容量の増え方は、**直前の容量から、決まった計算で**決まります（[5-3](#5-3-計算のしかた)）。

### 6-2. 1000個入れるまでの流れ

```text
 入れた数         容量
     1個目   →    4    （最初の32バイト）
     5個目   →    8    （4 がいっぱい → 引っ越し）
     9個目   →   16
       ⋮
   513個目   →  848    （512 がいっぱい → 引っ越し）
   849個目   → 1280    （848 がいっぱい → 引っ越し）   ← ここが最後の引っ越し
 850〜1000個目 → 1280 のまま（空きに入れていくだけ）

 1000個入れ終わったとき：容量 1280 − 長さ 1000 ＝ 空き 280
```

**849個目**で容量848がいっぱいになり、1280に引っ越しました。そのあと1000個目までは、空きに入れていくだけです。1000個で止めたので、**1280 − 1000 ＝ 280個**が余りました。

### 6-3. 何個入れるかで、空きの数が変わる

空きの数は、「**最後の引っ越しのあと、何個入れたか**」で決まります。

| 入れた数 | 容量 | 空き | 説明 |
|---|---|---|---|
| 848 | 848 | **0** | 848 にぴったり収まった |
| 849 | 1280 | **431** | 849個目で引っ越した直後。いちばん空きが多い |
| 1000 | 1280 | **280** | Q3 の例 |
| 1280 | 1280 | **0** | 1280 にぴったり収まった |
| 1281 | 1792 | **511** | 1281個目で、また引っ越した直後 |

```text
 容量 1280 の箱の列に、何個入っているか

  849個 ├■■■■■■■■■■■■■■■■■■■■■■■■■■■■■□□□□□□□□□□□□□□┤ 空き 431（引っ越した直後）
 1000個 ├■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■□□□□□□□□□┤ 空き 280
 1280個 ├■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■┤ 空き 0（ぴったり）
 1281個 → 1792 に引っ越し。空き 511
```

**引っ越した直後がいちばん空きが多く**、入れていくにつれて空きが減り、いっぱいになるとまた引っ越す、というくり返しです。

## 7. 容量を確保しないときの「余分」

`[]int` に、1000個を1個ずつ `append` したときの「余分」は、2種類あります。

### 7-1. 余分① 引っ越しのたびに捨てられる古い箱

引っ越しのたびに、**新しい箱の列を確保して、古い列を捨てます**（[go-buffer-size-and-append-qa.md の 5-5](go-buffer-size-and-append-qa.md#5-5-append-で空きがないとき大きい箱に引っ越す)）。

```text
 確保した箱の列（容量）

   4 → 8 → 16 → 32 → 64 → 128 → 256 → 512 → 848 → 1280
   捨  捨   捨   捨   捨    捨    捨    捨    捨    今使っている

   合計：4 + 8 + 16 + 32 + 64 + 128 + 256 + 512 + 848 + 1280 ＝ 3148個分
```

| | 箱の数 |
|---|---|
| 実際に必要だったのは | **1000個分** |
| 途中で確保した箱の合計 | **3148個分**（約3倍） |
| そのうち、捨てられた古い箱 | **1868個分**（4〜848 の合計） |

捨てられた箱は、あとで Go が片付けます（ゴミ集め）。片付けるのにも手間がかかります。それに加えて、引っ越しのたびに**中身を全部コピー**しています。

### 7-2. 余分② 最後に余る空きの箱

1000個入れ終わったとき、容量は **1280** です。**280個分の箱が、使われずに余っています**（[6章](#6-最後に余る空きの数はどう決まるか)）。

```text
 1000個入れ終わったとき

 ┌──────────────────────────────────────────┬──────────┐
 │■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■│□□□□□□□□□□│
 └──────────────────────────────────────────┴──────────┘
  └────────────── 長さ 1000 ─────────────────┘└ 空き 280 ┘
  └──────────────────── 容量 1280 ─────────────────────────┘
```

### 7-3. 容量を先に確保すると

`make([]int, 0, 1000)` で始めると、どちらの余分もなくなります。

| | 容量を確保しない | `make([]int, 0, 1000)` |
|---|---|---|
| 引っ越しの回数 | 10回 | **0回** |
| 確保した箱の合計 | 3148個分 | **1000個分** |
| 捨てられる古い箱 | 1868個分 | **0個** |
| 最後に余る箱 | 280個分 | **0個** |

> ただし、これは**最終的な数が分かっているとき**の話です。見当がつかないのに大きく確保すると、それこそ使わない箱が余ります（[go-buffer-size-and-append-qa.md の 8章](go-buffer-size-and-append-qa.md#8-長さと容量の使い分けまとめ)）。

## 8. まとめ

**メモリの1マスと、スライスの箱（Q4）**

- メモリの最小の単位は **1バイト（1マス）**。マスごとに**番地**が付いている
- スライスの**箱**は、**要素1個**のこと。`[]byte` の箱は1マス、`[]int` の箱は8マス
- 長さと容量は、**バイト数ではなく、箱（要素）の数**で数える

**型の大きさ（Q2）**

- `int` の大きさは、マシンによって変わる。**64ビットのマシンでは8バイト**
- `int32`、`uint16` のように数字が付いた型は、どのマシンでも大きさが決まっている（数字 ÷ 8 ＝ バイト数）
- 最初の容量は、Go が**最初に32バイト**確保することで決まる。`[]int` なら 32 ÷ 8 ＝ **4個**

**容量の増え方（Q1）**

- 基準は、**最初の容量**ではなく、**直前の容量**
- **小さいうちは2倍**、大きくなると**1.25倍に近づく**
- 計算した大きさは、**メモリの区切り**に切り上げられる。だから 848 や 1280 のような数字になる
- 細かいルールは Go のバージョンで変わるので、数字は覚えなくてよい

**空きと余分（Q1・Q3）**

- 最後に余る空きの数は、**ランダムではなく**、入れた数と増え方の計算で決まる（1000個なら必ず280個余る）
- 容量を確保しないと、**捨てられる古い箱**（1000個で1868個分）と、**最後に余る空き**（280個分）が出る
- 入れる数が分かっているなら、**最初から容量を確保**すると、引っ越しも余りも出ない

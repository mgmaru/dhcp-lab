# Q&A：ファイルとフォルダで権限（rwx）の意味が違う

[apt-permission-denied-qa.md](../troubleshooting/apt-permission-denied-qa.md) の「6. Linuxの権限のしくみ」を読んで出た質問と、その回答をまとめたメモです。

> **このドキュメントで一番大事なこと**
>
> **同じ `r`・`w`・`x` でも、ファイルとフォルダでは意味が違います。**
> 特に `x` は、ファイルでは「**プログラムとして実行する**」、フォルダでは「**中に入る**」という、まったく別の意味です。

## 質問

> nanoなどで書き込んだファイルを永続化（保存）する場合、書き込み権限だけではなく、実行権限も必要なのか？
>
> 「プログラムにアクセスする」と「プログラムを実行する」が同じことなのか、違うことなのかもよくわかっていない。

---

## 1. ファイルとフォルダで、rwxの意味が違う

2つの質問に答える前に、一番大事なことを説明します。

### 比較表

| 記号 | ファイルの場合 | フォルダの場合 |
|---|---|---|
| `r` | **中身を読める**（`cat`、`nano` で開く） | **中にあるファイルの名前の一覧を見られる**（`ls`） |
| `w` | **中身を書き換えられる**（保存する） | **中にファイルを作れる・消せる・名前を変えられる** |
| `x` | **プログラムとして実行できる**（`./hello.sh`） | **中に入れる**（`cd`、中のファイルにたどり着く） |

### 図で見る

```text
【ファイル】hello.sh                    【フォルダ】debs/
┌──────────────────────┐              ┌──────────────────────────────┐
│ #!/bin/sh            │              │  a.deb                       │
│ echo "Hello!"        │              │  b.deb                       │
└──────────────────────┘              └──────────────────────────────┘
 r … 中身（文字）を読む                  r … 「a.deb、b.deb がある」と一覧を見る
 w … 中身を書き換える                    w … ファイルを追加する・消す・名前を変える
 x … プログラムとして動かす               x … 中に入る（a.deb や b.deb にたどり着く）
```

### なぜ意味が違うのか

フォルダは、**「中にあるファイルの名前の一覧表」**のようなものだと考えるとわかりやすいです。

| | 中身 | `r` | `w` | `x` |
|---|---|---|---|---|
| ファイル | 文章やプログラム | 文章を読む | 文章を書き換える | プログラムとして動かす |
| フォルダ | **ファイルの名前の一覧表** | 一覧表を読む | 一覧表を書き換える（ファイルの追加・削除・名前の変更） | 一覧表を通って、中のファイルにたどり着く |

フォルダはプログラムではないので、「実行する」ことはできません。そこでフォルダの `x` には、「中に入る」という別の意味が割り当てられています。

### 例え：建物と部屋の中の書類

```text
 フォルダ ＝ 部屋        ファイル ＝ 部屋の中の書類

 部屋の x（中に入れるか）がないと、
 書類の権限がどうであっても、書類のところまで行けない
```

| 権限 | 部屋（フォルダ） | 書類（ファイル） |
|---|---|---|
| `r` | 部屋の中に何があるか、ドアの窓から一覧を見られる | 書類を読める |
| `w` | 部屋に書類を持ち込む・捨てる・ラベルを貼り替える | 書類に書き込める |
| `x` | **部屋に入れる** | 書類の内容どおりに**作業を実行する** |

## 2. Q1. nanoで書いたファイルを保存するのに、実行権限も必要か？

### 結論

**必要ありません。ファイルの `x`（実行）は、保存とは関係ありません。**

ファイルを保存するのは「**書き込み**」です。必要なのは、**ファイルの `w`** と、そのファイルまでたどり着くための**フォルダの `x`** です。

### 必要な権限

| やりたいこと | ファイルに必要な権限 | フォルダに必要な権限 |
|---|---|---|
| 既存のファイルをnanoで開いて、編集して保存する | `r`（開く）＋ `w`（保存する） | `x`（中に入る） |
| nanoで**新しいファイル**を作って保存する | （まだファイルがない） | `w`（ファイルを作る）＋ `x`（中に入る） |

### 例：`~/memo.txt` をnanoで編集して保存する

```text
 /home/kajih/   drwx------  → 持ち主（kajih）に x あり  ✅ 中に入れる（フォルダの x）
 └ memo.txt     -rw-r--r--  → 持ち主（kajih）に r と w あり  ✅ 開けて保存できる
                   └ ファイルの x はなくてOK
```

ここで出てくる `x` は**フォルダの `x`**（中に入る）です。ファイルの `x`（実行する）ではありません。

### 補足：「永続化」は保存する場所の問題

保存したファイルが再起動後も残るかどうかは、**権限ではなく、保存した場所**で決まります。

| 保存した場所 | 再起動後に残るか |
|---|---|
| `/home/kajih`（`~`）の中 | 残る |
| `/tmp` の中 | **残らない**（Debian 13では、`/tmp` はメモリ上にあり、再起動で空になる） |

## 3. Q2. 「アクセスする」と「実行する」は同じことか？

### 結論

**違うことです。**

混乱しやすいのは、**同じ `x` という文字が、ファイルとフォルダで別の意味を持つ**からです。

| | ファイルの `x` | フォルダの `x` |
|---|---|---|
| 意味 | **プログラムとして実行する** | **中に入る**（中のファイルにたどり着く） |
| 例 | `./hello.sh` を動かす | `cd ~/debs` で移動する、`~/debs/a.deb` を読みに行く |

[apt-permission-denied-qa.md](../troubleshooting/apt-permission-denied-qa.md) の6-3で「フォルダの `x`」を説明したときの「アクセス」は、**中のファイルにたどり着ける**という意味です。中のファイルを**実行する**という意味ではありません。

### ファイルを「読む」と「実行する」の違い

ファイルについて、2つの操作を比べます。

| 操作 | 何をしているか | 必要な権限 | 例 |
|---|---|---|---|
| 読む | ファイルの**中身を見る**（文字として扱う） | ファイルの `r` | `cat hello.sh`、`nano hello.sh` |
| 実行する | ファイルを**プログラムとして動かす** | ファイルの `x` | `./hello.sh` |

例えると、レシピの紙を**読む**ことと、そのレシピどおりに**料理を作る**ことの違いです。

```text
 hello.sh の中身
 ┌──────────────────────┐
 │ #!/bin/sh            │
 │ echo "Hello!"        │
 └──────────────────────┘

 読む（r）    → 画面に「#!/bin/sh」「echo "Hello!"」という文字が表示される
 実行する（x）→ 中の命令が動いて、画面に「Hello!」と表示される
```

### 3つの言葉の整理

| 言葉 | 意味 | 関係する権限 |
|---|---|---|
| ファイルを**読む** | 中身を文字として見る | ファイルの `r` |
| ファイルを**実行する** | プログラムとして動かす | ファイルの `x` |
| ファイルに**たどり着く**（アクセスする） | ファイルがあるフォルダの中に入る | **フォルダ**の `x` |

## 4. 実際に試してみる

違いを手で確かめられます。Client VMやRouter VMで試してみてください。

### 4-1. ファイルの r と x の違い

**準備：小さなプログラムを作る**

```bash
cd ~
printf '#!/bin/sh\necho "Hello!"\n' > hello.sh
ls -l hello.sh
```

```text
-rw-r--r-- 1 kajih kajih 27 Oct 15 10:00 hello.sh
   └ x がない
```

**① 読む（`r` があるのでできる）**

```bash
cat hello.sh
```

```text
#!/bin/sh
echo "Hello!"
```

**② 実行する（`x` がないのでできない）**

```bash
./hello.sh
```

```text
-bash: ./hello.sh: Permission denied
```

**③ 実行権限を付けてから実行する**

```bash
chmod +x hello.sh
ls -l hello.sh
./hello.sh
```

```text
-rwxr-xr-x 1 kajih kajih 27 Oct 15 10:00 hello.sh
   └ x が付いた
Hello!
```

> **ちょっと面白い例**
>
> `x` がなくても、`sh hello.sh` と書けば動きます。これは `sh` というプログラムが hello.sh を**読んで**（`r`）、中に書かれた命令を実行しているからです。実行されているのは `sh` で、hello.sh は「読まれる側」です。

### 4-2. フォルダの r と x の違い

**準備：フォルダとファイルを作る**

```bash
mkdir ~/testdir
echo "secret" > ~/testdir/a.txt
```

**① フォルダの `x` を外す（`r` だけにする）**

```bash
chmod 600 ~/testdir      # rw-------（持ち主の x を外す）
ls ~/testdir             # 一覧は見られる（r があるから）
cat ~/testdir/a.txt      # 中のファイルは読めない（x がないから）
cd ~/testdir             # 中に入れない（x がないから）
```

```text
ls: cannot access '/home/kajih/testdir/a.txt': Permission denied
a.txt
cat: /home/kajih/testdir/a.txt: Permission denied
-bash: cd: /home/kajih/testdir: Permission denied
```

> `ls` は名前（`a.txt`）だけは表示できます。ただし、環境によっては（Debianの標準設定のように `ls` が色付き表示になっている場合など）、ファイルの詳しい情報を取ろうとして `ls: cannot access ...` のエラーも一緒に出ます。名前の一覧は `r` で見られても、中のファイルにたどり着くには `x` が必要だからです。

**② フォルダの `r` を外す（`x` だけにする）**

```bash
chmod 300 ~/testdir      # -wx------（持ち主の r を外す）
ls ~/testdir             # 一覧は見られない（r がないから）
cat ~/testdir/a.txt      # 名前を知っていれば読める（x があるから）
```

```text
ls: cannot open directory '/home/kajih/testdir': Permission denied
secret
```

| フォルダの権限 | `ls`（一覧を見る） | `cat`（中のファイルを読む） | `cd`（中に入る） |
|---|---|---|---|
| `r` だけ（`600`） | ✅（名前だけ） | ❌ | ❌ |
| `x` だけ（`300`） | ❌ | ✅（名前を知っていれば） | ✅ |
| `r` と `x`（`700`） | ✅ | ✅ | ✅ |

### 4-3. 後片付け

```bash
chmod 700 ~/testdir
rm -r ~/testdir ~/hello.sh
```

## 5. 操作ごとに必要な権限の早見表

| 操作 | ファイルの権限 | そのファイルがあるフォルダの権限 |
|---|---|---|
| 中身を読む（`cat`、`nano` で開く） | `r` | `x` |
| 中身を書き換えて保存する | `w` | `x` |
| 新しいファイルを作る | — | `w` ＋ `x` |
| ファイルを消す・名前を変える | **不要** | `w` ＋ `x` |
| プログラムとして実行する | `x`（スクリプトなら `r` も） | `x` |
| フォルダの中の一覧を見る（`ls`） | — | `r`（詳しく見るなら `x` も） |

> **意外なポイント：ファイルを消せるかどうかは、フォルダの権限で決まる**
>
> ファイルを消すのは、「フォルダの一覧表から名前を消す」操作です。そのため、**フォルダの `w`** が必要で、ファイル自体の権限は関係ありません。
>
> `/tmp` は誰でも `w` を持っているので、本来は他人のファイルも消せてしまいます。それを防ぐのが、スティッキービット（`t`）です（[apt-permission-denied-qa.md の6-4](../troubleshooting/apt-permission-denied-qa.md#6-4-記号での表し方drwx-------の読み方)）。

> 「そのファイルがあるフォルダ」だけでなく、`/` からそこまでの**道のりにあるすべてのフォルダ**にも `x` が必要です（[apt-permission-denied-qa.md の7章](../troubleshooting/apt-permission-denied-qa.md#7-今回の事例を権限で読み解く)）。

> root（`sudo` を付けたコマンド）は、権限のチェックをほぼ受けないので、この表に関係なく読み書きできます。ただし、ファイルの実行だけは、誰かに `x` が付いていないとrootでもできません。

## 6. まとめ

- **同じ `r`・`w`・`x` でも、ファイルとフォルダでは意味が違う**

  | 記号 | ファイル | フォルダ |
  |---|---|---|
  | `r` | 中身を読む | 名前の一覧を見る |
  | `w` | 中身を書き換える | ファイルを作る・消す・名前を変える |
  | `x` | **プログラムとして実行する** | **中に入る** |

- nanoで保存するのに必要なのは、**ファイルの `w`** と**フォルダの `x`**。**ファイルの `x` は不要**
- 「読む（ファイルの `r`）」「実行する（ファイルの `x`）」「たどり着く（フォルダの `x`）」は、それぞれ別のこと
- ファイルを消せるかどうかは、**フォルダの `w`** で決まる
- 再起動後もファイルが残るかどうかは、権限ではなく**保存する場所**で決まる

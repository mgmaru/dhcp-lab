## 1. 何が起こったのか

### 状況

- Router VMで `.deb` ファイルをダウンロードし、`scp` でClient VMの `~/debs/` にコピーした
- Client VMで、コピーした `.deb` ファイルからインストールしようとした

### 実行したコマンド

```bash
sudo apt install -y ~/debs/*.deb
```

### 出たエラー（抜粋）

```text
Note, selecting 'tcpdump' instead of '/home/kajih/debs/tcpdump_4.99.5-2_amd64.deb'
...
Installing:
  libpcap0.8t64  netcat-openbsd  socat  tcpdump
...
Err:4 http://deb.debian.org/debian trixie/main amd64 tcpdump amd64 4.99.5-2
  Temporary failure resolving 'deb.debian.org'
  File not found - /home/kajih/debs/tcpdump_4.99.5-2_amd64.deb (13: Permission denied)
...
Error: Failed to fetch file:/home/kajih/debs/tcpdump_4.99.5-2_amd64.deb  File not found - /home/kajih/debs/tcpdump_4.99.5-2_amd64.deb (13: Permission denied)
Error: Unable to fetch some archives, maybe run apt-get update or try with --fix-missing?
```

### エラーの読み方

| 表示 | 意味 | 問題か |
|---|---|---|
| `Note, selecting 'tcpdump' instead of '/home/kajih/debs/...'` | ファイルを指定したので、そのパッケージ（tcpdump）を入れます、というお知らせ | 問題なし |
| `Temporary failure resolving 'deb.debian.org'` | aptが、まずインターネットから取ろうとして失敗した | Client VMはインターネットに出られないので**想定どおり** |
| `File not found ... (13: Permission denied)` | 次に、手元のファイルから取ろうとしたが、**読む権限がなかった** | **これが本当の原因** |

> `File not found` と書かれていますが、ファイルがないわけではありません。最後の `(13: Permission denied)` が本当の理由で、「ファイルはあるが、読む権限がない」という意味です。

インターネットからも、手元のファイルからも取れなかったので、最後にエラーになりました。

---

## 2. 原因

### 一言でいうと

aptがファイルを読むときに使う **`_apt` ユーザー**が、**`/home/kajih` の中に入れなかった**ことが原因です。

### もう少し詳しく

1. `apt` は安全のため、パッケージファイルを**取得するときだけ**、`root` ではなく `_apt` という権限の弱い専用ユーザーに切り替える
2. 今回のパッケージファイルは `/home/kajih/debs/` に置いてあった
3. `/home/kajih` は、**持ち主の kajih しか入れない**設定になっていた
4. そのため、`_apt` は `/home/kajih/debs/` のファイルを読めなかった

```text
 sudo apt install ~/debs/*.deb
   │
   ├─ インストール処理 ……………… root で実行
   └─ ファイルの取得 ………………… _apt ユーザーで実行 ← ここで失敗
                                    │
                                    ▼
                           /home/kajih/  （kajih 本人しか入れない）
                             └ debs/*.deb   → Permission denied
```

### 確認する方法

```bash
ls -ld ~
```

```text
drwx------ ... kajih kajih ... /home/kajih
```

`drwx------` は、「持ち主（kajih）だけが中に入れて、ほかのユーザー（`_apt` を含む）は入れない」という意味です。この記号の読み方は、[6章](#6-linuxの権限のしくみ)で詳しく説明します。

> 最近のDebian（今回使っている Debian 13 trixie を含む）では、新しく作ったユーザーのホームディレクトリは、標準で本人しか入れない設定になります。

## 3. 対処法

どちらか1つを実行します。

### 方法1：`_apt` が読める場所にコピーしてからインストールする（おすすめ）

Client VMで実行します。

```bash
mkdir -p /tmp/debs
cp ~/debs/*.deb /tmp/debs/
chmod 755 /tmp/debs
chmod 644 /tmp/debs/*.deb
sudo apt install -y /tmp/debs/*.deb
```

| コマンド | 意味 |
|---|---|
| `mkdir -p /tmp/debs` | 全ユーザー共有の一時置き場 `/tmp` の下に `debs` フォルダを作る。`-p` は「すでにあってもエラーにしない」という意味 |
| `cp ~/debs/*.deb /tmp/debs/` | 自分のホームから `/tmp/debs` へコピーする |
| `chmod 755 /tmp/debs` | フォルダに、ほかのユーザーも入れるようにする |
| `chmod 644 /tmp/debs/*.deb` | ファイルを、ほかのユーザーも読めるようにする |
| `sudo apt install -y /tmp/debs/*.deb` | `/tmp/debs` のファイルからインストールする |

`chmod 755` や `644` の意味は、[6-5](#6-5-数字での表し方755644)で説明します。

### 方法2：`dpkg` で直接インストールする

```bash
sudo dpkg -i ~/debs/*.deb
```

`dpkg` は、aptの下で実際にインストールを行っているコマンドです。`dpkg` は `_apt` ユーザーに切り替えず、`root` のままファイルを読むので、ホームディレクトリの中でも読めます。

| | apt | dpkg |
|---|---|---|
| ファイルを読むユーザー | `_apt` | `root` |
| 足りない依存パッケージ | 自動で取ってくる（インターネットに出られれば） | **取ってこない**。自分で用意する |

今回は依存パッケージ（`libpcap0.8t64`）も同じコマンドで一緒に指定しているので、インストールできるはずです。

### やめておいたほうがよい方法

`chmod 755 ~` でホームディレクトリをほかのユーザーにも開放すると、aptは読めるようになります。ただし、ホームの中身を**誰でも見られる**状態になるので、おすすめしません。

### インストールできたか確認する

```bash
nc -h 2>&1 | head -1
socat -V | head -1
tcpdump --version | head -1
```

3つとも表示されれば完了です。

## 4. Q1. aptを実行したら、自動で `_apt` に降格させられたのか？

> root権限でaptを実行した場合、OS側が自動的に、root権限ではなく `_apt` 権限に降格させて apt install を実行した、という認識でよいか？

### 結論

**ほぼ合っています。ただし、2点だけ補足があります。**

### 補足1：降格させているのはOSではなく、apt自身

OSが自動で権限を下げたのではありません。**aptというプログラムが、自分で権限を手放す**ように作られています。

このように、危ない作業だけ権限の弱いユーザーで行うしくみを**権限分離**と呼びます。

| 誤解しやすい理解 | 正しい理解 |
|---|---|
| OSが、aptの権限を勝手に下げた | aptが、自分の判断で権限を手放した |

### 補足2：降格するのは「ファイルの取得」の部分だけ

`apt install` 全体が `_apt` で動くわけではありません。

```text
 sudo apt install ...
   │
   ├─ ① 依存関係の計算          …… root
   ├─ ② パッケージファイルの取得  …… _apt   ← 今回失敗したのはここ
   │     （インターネットからのダウンロード、手元のファイルの読み込み）
   └─ ③ インストール（dpkg）     …… root
```

| 処理 | 実行するユーザー | 理由 |
|---|---|---|
| ② ファイルの取得 | `_apt` | インターネットから来るデータは信用できない。万一、悪意のあるデータでaptの不具合を突かれても、`_apt` ならできることが少なく、被害を小さくできる |
| ③ インストール | `root` | `/usr/bin` などのシステムの場所にファイルを置くには、root の権限が必要 |

> 3章の方法2で紹介した `dpkg` は、③の部分だけを行うコマンドです。②がないので、root のままファイルを読めます。

### `_apt` ユーザーとは

`_apt` は、人がログインするためのユーザーではありません。**aptが使うためだけに用意された**ユーザーです。このようなユーザーを**システムユーザー**と呼びます。

```bash
getent passwd _apt
```

出力例：

```text
_apt:x:42:65534::/nonexistent:/usr/sbin/nologin
```

`:` で区切られた各項目の意味は次のとおりです。

| 位置 | 値 | 意味 |
|---|---|---|
| 1 | `_apt` | ユーザー名 |
| 2 | `x` | パスワード（実際は別のファイルに保存されている） |
| 3 | `42` | ユーザーID（UID）。OSはユーザーを名前ではなく、この番号で区別する |
| 4 | `65534` | 所属するグループのID（GID） |
| 5 | （空） | 説明 |
| 6 | `/nonexistent` | ホームディレクトリ。**存在しない場所**を指定している（ホームを持たない） |
| 7 | `/usr/sbin/nologin` | ログインしたときに起動するシェル。**ログインできない**ようにしている |

## 5. Q2. `/tmp/debs` は、ユーザー領域とは別の場所なのか？

> 対処法に `mkdir -p /tmp/debs` とあるが、これはユーザー領域とは別のところなのか？

### 結論

**はい、別の場所です。**

| 場所 | 役割 |
|---|---|
| `/home/kajih`（`~`） | **kajih 専用**の場所 |
| `/tmp` | **全ユーザーが共有**で使える一時置き場 |

### Linuxのフォルダ構成

Linuxでは、すべてのファイルが `/`（ルート）から始まる**1本の木**の中にあります。Windowsのように `C:` や `D:` に分かれていません。

```text
/                     ← 全体の出発点（ルート）
├── home/             ← 一般ユーザーのホームディレクトリが集まる場所
│   └── kajih/        ← kajih 専用（= ~）。本人しか入れない
│       └── debs/        ← scp でコピーした場所（_apt は読めない）
├── root/             ← root ユーザーのホームディレクトリ
├── tmp/              ← 全ユーザー共有の一時置き場
│   └── debs/            ← 今回コピーし直す場所（_apt も読める）
├── etc/              ← 設定ファイル
├── usr/              ← インストールしたプログラム（/usr/bin/tcpdump など）
└── var/              ← ログなど、中身が変わっていくファイル
```

| 場所 | 用途 | 読める人 | 書ける人 |
|---|---|---|---|
| `/home/kajih`（`~`） | kajih の個人ファイル | kajih だけ | kajih だけ |
| `/root` | root の個人ファイル | root だけ | root だけ |
| `/tmp` | 一時的なファイル | 全員 | **全員**（ただし他人のファイルは消せない） |
| `/etc` | システムの設定ファイル | 全員 | root だけ |
| `/usr` | インストールしたプログラム | 全員 | root だけ |
| `/var` | ログやキャッシュなど | ものによる | 主に root |

> 「`/root`」と「`/`（ルート）」は別物です。`/` はフォルダ構成全体の出発点、`/root` は root ユーザーのホームディレクトリです。どちらも「ルート」と読むので注意してください。

### `/tmp` の注意点

| 注意点 | 説明 |
|---|---|
| **再起動すると消えることがある** | Debian 13 では、標準で `/tmp` がメモリ上に作られるので、再起動すると空になる。大事なファイルは置かない |
| **誰でも見られる** | パスワードなどの秘密の情報は置かない。今回のパッケージファイルのように、見られても困らないファイルなら問題ない |

## 6. Linuxの権限のしくみ

今回の原因を理解するために必要な、Linuxの権限のしくみを基本から説明します。

### 6-1. ユーザーとグループ

Linuxでは、**誰が**操作しているかを、**ユーザー**と**グループ**で管理しています。

| 用語 | 意味 | 例 |
|---|---|---|
| ユーザー | 操作する人やプログラムの単位 | `kajih`、`root`、`_apt` |
| グループ | ユーザーをまとめたもの。グループ単位で権限を与えられる | `kajih`、`sudo` |
| root | **何でもできる特別なユーザー**（管理者）。権限のチェックをほぼ受けない | `root` |

自分が誰で、どのグループに入っているかは、`id` コマンドで確認できます。

```bash
id
```

出力例：

```text
uid=1000(kajih) gid=1000(kajih) groups=1000(kajih),27(sudo)
```

| 部分 | 意味 |
|---|---|
| `uid=1000(kajih)` | ユーザーIDは1000、名前は kajih |
| `gid=1000(kajih)` | 主に所属するグループは kajih |
| `groups=...,27(sudo)` | sudo グループにも入っている（だから `sudo` が使える） |

> Debianでは、ユーザーを作ると、同じ名前のグループも自動で作られます。そのため、ユーザー `kajih` とグループ `kajih` が両方あります。

### 6-2. ファイルには「持ち主」と「グループ」がある

すべてのファイルとフォルダには、**持ち主（所有者）**と**グループ**が決まっています。

```bash
ls -l /tmp/debs
```

出力例：

```text
-rw-r--r-- 1 kajih kajih 123456 Oct 15 10:00 tcpdump_4.99.5-2_amd64.deb
└─権限──┘   └持ち主┘└グループ┘└サイズ┘└─更新日時─┘ └──── ファイル名 ────┘
```

### 6-3. 権限は「誰に」×「何を」の組み合わせ

権限は、**3種類の相手**に対して、**3種類の操作**を許すかどうかで決まります。

**誰に（3種類の相手）**

| 相手 | 記号 | 意味 |
|---|---|---|
| 持ち主 | `u`（user） | そのファイルの持ち主 |
| グループ | `g`（group） | そのファイルのグループに入っているユーザー |
| その他 | `o`（others） | 上のどちらにも当てはまらない、**それ以外の全員** |

**何を（3種類の操作）**

| 記号 | 名前 | ファイルの場合 | フォルダの場合 |
|---|---|---|---|
| `r` | 読み取り（read） | 中身を読める | 中にあるファイルの**名前の一覧**を見られる |
| `w` | 書き込み（write） | 中身を書き換えられる | 中にファイルを**作れる・消せる・名前を変えられる** |
| `x` | 実行（execute） | プログラムとして実行できる | フォルダの**中に入れる**（中のファイルにアクセスできる） |

> **フォルダの `x` が大事**
>
> フォルダの `x` は「中に入る」権限です。**フォルダに `x` がないと、その中のファイルには、ファイル自体の権限に関係なくアクセスできません。**
>
> 今回の原因は、まさにこれです。`/home/kajih/debs/*.deb` のファイル自体は誰でも読める設定（`644`）でも、手前の `/home/kajih` に「その他」の `x` がないので、`_apt` は中に入れませんでした。

### 6-4. 記号での表し方（`drwx------` の読み方）

`ls -l` や `ls -ld` の先頭10文字が権限です。

```text
 d  rwx  r-x  r-x
 │  └┬┘  └┬┘  └┬┘
 │   │    │    └── その他（o）
 │   │    └─────── グループ（g）
 │   └──────────── 持ち主（u）
 └──────────────── 種類（d = フォルダ、- = ファイル）
```

各3文字は、左から `r`・`w`・`x` の順に並んでいて、権限がないところは `-` になります。

**例1：`/home/kajih`（`drwx------`）**

| 相手 | 記号 | 意味 |
|---|---|---|
| 種類 | `d` | フォルダ |
| 持ち主（kajih） | `rwx` | 一覧を見る・作る／消す・中に入る、すべてできる |
| グループ | `---` | 何もできない |
| その他（`_apt` はここ） | `---` | **何もできない（中に入れない）** |

**例2：`/tmp`（`drwxrwxrwt`）**

| 相手 | 記号 | 意味 |
|---|---|---|
| 種類 | `d` | フォルダ |
| 持ち主（root） | `rwx` | すべてできる |
| グループ | `rwx` | すべてできる |
| その他 | `rwt` | すべてできる。ただし `t`（スティッキービット）付き |

> **スティッキービット（`t`）とは**
>
> フォルダに付ける特別な権限で、「**誰でもファイルを作れるが、消したり名前を変えたりできるのは、自分が作ったファイルだけ**」という意味です。
>
> `/tmp` は全員が使う共有の場所なので、他人のファイルを勝手に消せないように、スティッキービットが付いています。

**例3：コピーした `.deb` ファイル（`-rw-r--r--`）**

| 相手 | 記号 | 意味 |
|---|---|---|
| 種類 | `-` | ファイル |
| 持ち主 | `rw-` | 読める・書ける |
| グループ | `r--` | 読めるだけ |
| その他 | `r--` | 読めるだけ |

### 6-5. 数字での表し方（`755`・`644`）

`chmod 755` のように、権限は**3桁の数字**でも表せます。`r`・`w`・`x` にそれぞれ点数を付けて、足し算します。

| 権限 | 点数 |
|---|---|
| `r`（読む） | **4** |
| `w`（書く） | **2** |
| `x`（実行・中に入る） | **1** |
| なし | 0 |

1桁目が持ち主、2桁目がグループ、3桁目がその他です。

```text
 755  →  7      5      5
         │      │      │
        持ち主  グループ  その他
        4+2+1  4+0+1  4+0+1
        rwx    r-x    r-x
```

**よく使う組み合わせ**

| 数字 | 記号 | 意味 | よく使う対象 |
|---|---|---|---|
| `755` | `rwxr-xr-x` | 持ち主は全部、ほかの人は読む・入る（実行する） | フォルダ、プログラム |
| `644` | `rw-r--r--` | 持ち主は読み書き、ほかの人は読むだけ | 普通のファイル |
| `700` | `rwx------` | 持ち主だけが全部できる | 本人専用のフォルダ（今回の `/home/kajih`） |
| `600` | `rw-------` | 持ち主だけが読み書きできる | 秘密のファイル（SSHの秘密鍵など） |

**1桁あたりの数字の早見表**

| 数字 | 記号 | 計算 |
|---|---|---|
| 7 | `rwx` | 4+2+1 |
| 6 | `rw-` | 4+2 |
| 5 | `r-x` | 4+1 |
| 4 | `r--` | 4 |
| 0 | `---` | 0 |

### 6-6. 権限を確認・変更するコマンド

| コマンド | 意味 | 例 |
|---|---|---|
| `ls -l ファイル` | ファイルの権限を見る | `ls -l /tmp/debs` |
| `ls -ld フォルダ` | フォルダ**そのもの**の権限を見る（`-d` がないと中身の一覧になる） | `ls -ld ~` |
| `chmod 数字 対象` | 権限を変える | `chmod 644 a.txt` |
| `chmod 記号 対象` | 権限を一部だけ変える | `chmod o+r a.txt`（その他に読む権限を足す） |
| `id` | 自分のユーザーとグループを見る | `id` |
| `id ユーザー名` | ほかのユーザーの情報を見る | `id _apt` |

> `chmod` で権限を変えられるのは、そのファイルの**持ち主**か**root**だけです。

### 6-7. sudo と root

| 用語 | 意味 |
|---|---|
| `root` | 何でもできる管理者ユーザー |
| `sudo` | 「このコマンドだけ root として実行する」ためのコマンド。`sudo` グループに入っているユーザーが使える |

```text
 kajih が ls を実行            → kajih の権限で動く
 kajih が sudo apt を実行      → root の権限で動く（パスワードを聞かれる）
   └─ apt がファイル取得のときだけ _apt に切り替える（今回の話）
```

> rootは権限のチェックをほぼ受けないので、`/home/kajih` の中にも入れます。`sudo dpkg -i ~/debs/*.deb`（3章の方法2）が成功するのはこのためです。

## 7. 今回の事例を権限で読み解く

6章の知識で、今回起こったことを順番に見ていきます。

### `_apt` が `/home/kajih/debs/tcpdump_....deb` を読もうとしたとき

ファイルを読むには、**そこまでの道のりにあるすべてのフォルダに `x`（中に入る）権限**が必要です。

```text
 /            drwxr-xr-x  root   → その他に x あり  ✅ 入れる
 └ home/      drwxr-xr-x  root   → その他に x あり  ✅ 入れる
   └ kajih/   drwx------  kajih  → その他に x なし  ❌ ここで止まる
     └ debs/
       └ tcpdump_....deb  -rw-r--r--  （ファイル自体は誰でも読める設定だが、ここまでたどり着けない）
```

`_apt` は持ち主（kajih）でも、グループ（kajih）のメンバーでもないので、「**その他**」の権限で判定されます。`/home/kajih` の「その他」は `---` なので、中に入れず `Permission denied` になりました。

### `/tmp/debs/tcpdump_....deb` に置き直したとき

```text
 /            drwxr-xr-x  root   → その他に x あり  ✅ 入れる
 └ tmp/       drwxrwxrwt  root   → その他に x あり  ✅ 入れる
   └ debs/    drwxr-xr-x  kajih  → その他に x あり  ✅ 入れる（chmod 755）
     └ tcpdump_....deb  -rw-r--r--  kajih → その他に r あり  ✅ 読める（chmod 644）
```

道のりのすべてのフォルダに入れて、ファイルも読めるので、`_apt` がファイルを取得できます。

### 自分の環境で確かめる

`namei -l` を使うと、道のりのフォルダの権限をまとめて表示できます。

```bash
namei -l /home/kajih/debs
namei -l /tmp/debs
```

出力例：

```text
f: /home/kajih/debs
drwxr-xr-x root  root  /
drwxr-xr-x root  root  home
drwx------ kajih kajih kajih    ← ここで「その他」の権限がなくなる
drwxr-xr-x kajih kajih debs
```

## 8. まとめ

**今回のエラー**

- `sudo apt install ~/debs/*.deb` が `Permission denied` で失敗した
- aptはファイルの取得を**`_apt` ユーザー**で行う。`_apt` は `/home/kajih` に入れなかった
- 対処は、`/tmp/debs` にコピーしてから `apt install` する（または `sudo dpkg -i` を使う）

**Q1：権限の降格**

- 降格させているのは**apt自身**（権限分離）。OSが勝手に降格させるわけではない
- 降格するのは**ファイルの取得の部分だけ**。インストールそのものは root で行う

**Q2：`/tmp` とホームディレクトリ**

- `/home/kajih` は**本人専用**、`/tmp` は**全ユーザー共有の一時置き場**
- `/tmp` は再起動で消えることがあり、誰でも見られるので、大事なファイルや秘密の情報は置かない

**Linuxの権限**

- 権限は「**持ち主・グループ・その他**」×「**読む（r）・書く（w）・実行／中に入る（x）**」の組み合わせ
- 数字では `r=4`、`w=2`、`x=1` を足して表す（例：`755` = `rwxr-xr-x`、`644` = `rw-r--r--`）
- ファイルを読むには、**道のりのすべてのフォルダに `x` 権限**が必要
- `/tmp` の `t`（スティッキービット）は、「誰でも作れるが、消せるのは自分のファイルだけ」という意味

### 1回目：最初のコード

**コードの内容**

- `ResolveUDPAddr("udp4", "10.0.0.10:9068")` で住所を作り、`ListenUDP("udp4", addr)` で bind する
- エラーのときは、`fmt.Fprintln(os.Stderr)` を呼んで、`os.Exit(1)` で終わる
- `defer conn.Close()` で、後片付けを予約する

**できていたこと**

| できていたこと | 説明 |
|---|---|
| ✅ `"udp4"` を指定している | IPv4 に限定できている（Server の3〜6回目で学んだこと） |
| ✅ `DialUDP` ではなく `ListenUDP` を選んでいる | `DialUDP` だと接続済みになり、決めた相手以外からの返事を受け取れない。ブロードキャストで送って `10.0.0.1` から返事が来る場合に困る（README の手がかり3） |
| ✅ 9068番に bind しようとしている | 要件 C1 |
| ✅ エラーで止まり、終了コード 1 で終わる | Server で身につけた形 |
| ✅ `defer conn.Close()` がエラー確認の直後にある | 一般的な位置 |

**できていなかったこと**

| # | 重要度 | 問題 | なぜ問題か |
|---|---|---|---|
| 1 | 🔴 | **`fmt.Fprintln(os.Stderr)` に `err` を渡していない** | 書く中身を渡していないので、**空行が1行**出るだけ。なぜ失敗したのかが分からない |
| 2 | 🟡 | **自分側のIPアドレスを `10.0.0.10` に固定している** | `10.0.0.10` を持っていないマシンでは bind できない。Client VM のIPアドレスが変わっても失敗する（下の補足） |

### 3回目：ミニフォーマットを組み立てて送る

**コードの内容**

- `flag` で、種類（`-kinds`、`int`）・ID（`-ID`、`uint`）・本文（`-message`、`string`）を受け取る。`flag.Parse()` はソケットを作る**前**
- 種類が「1か2」でなければ、ID が `math.MaxUint32` より大きければ、全体の長さが1000バイトより長ければ、エラーを表示する
- 長さ（1 ＋ 4 ＋ 本文のバイト数）を計算して、その長さで `buf` を作る
- 自分側の住所 `:9068` と、宛先の住所 `:9067` を作る。`ListenUDP` で bind する
- 種類を `buf[0]` に代入、ID を `PutUint32(buf[1:5], …)` で書き、本文を `copy(buf[5:], …)` で写す
- `WriteToUDP` で宛先に送る。エラーなら表示する
- 種類・ID・本文を表示する

**直したこと**

| 直したこと | 前の回の問題 |
|---|---|
| ✅ 自分側の住所を**ポートだけ**（`:9068`）にした。Mac でも bind できる | 1回目 #2 |
| ✅ 変数名を `clientAddr`・`serverAddr` にして、**何の住所か**分かるようにした | 1回目 #3 |

**できていたこと**

| できていたこと | 説明 |
|---|---|
| ✅ **組み立てが正しい** | 種類は `buf[0]` に直接代入、ID は `PutUint32(buf[1:5], …)`、本文は `copy(buf[5:], …)`。Server が受け取ったバイトが `01 00 00 00 01 68 69` で、決めたとおりの位置に入っていた |
| ✅ `buf` の長さが**ちょうど** | 1 ＋ 4 ＋ 本文のバイト数で作っているので、余計な0が送られない（[go-send-buffer-and-copy-qa.md](../qa/go-send-buffer-and-copy-qa.md) の2章） |
| ✅ 中間の `[]byte` を作らず、`buf` に**直接**書いている | 確保は `make` の1回だけ |
| ✅ 送るメソッドに `WriteToUDP` を選んだ | `ListenUDP` で作ったソケットは接続済みではないので、**宛先を毎回指定する**メソッドが必要（2回目の「次にやること」4） |
| ✅ `flag.Parse()` とチェックを、ソケットを作る**前**に置いた | 引数が間違っていたら、ソケットを作らずに終われる形になっている |
| ✅ 種類を「**1か2**」に絞った | 0〜255 より厳しいので、`byte` への変換で値が壊れない |
| ✅ ID の範囲を `math.MaxUint32` で確かめている | 4294967295 を直接書かずに済み、意味が分かる。`uint` には「0より小さい」チェックが要らないことにも気づけた |
| ✅ 全体の長さを、Server の入れ物（1000バイト）以下に制限した | Server で黙って切られるのを防げる |
| ✅ `:=` と `=` を使い分けた | `err` は作り済みなので、送信の行は `=` |

**できていなかったこと**

| # | 重要度 | 問題 | なぜ問題か |
|---|---|---|---|
| 4 | 🔴 | **宛先の住所にIPアドレスがない**（`":9067"`） | ポートだけの住所は、bind する側では「自分の全部のアドレスで受ける」意味になるが、送る側では**送り先が決まらない**。Mac では `sendto: no route to host` で送信に失敗した |
| 5 | 🔴 | **引数のチェックに引っかかっても、終了しない** | エラーを表示した後もそのまま進む。`-ID 4294967297` では、エラーの後に**送信しようとした**。範囲外の値は、`byte`・`uint32` への変換で**黙って切り捨てられて**送られる（[integer-size-and-byte-format-qa.md](../qa/integer-size-and-byte-format-qa.md) の9章） |
| 6 | 🔴 | **送信に失敗しても、終了しない** | #4 のエラーの後も、「送ったもの」の表示まで進んだ。送れていないのに、送れたように見える |
| 7 | 🟡 | **種類と ID の表示が文字化けする** | `string(buf[0])` は、値 `1` を**番号1の文字**（目に見えない文字）に変換する。`string(buf[1:5])` も、4バイトを**文字として**読んでいる。Server のレビュー8回目と同じ現象 |
| 8 | 🟡 | **返事を受け取る処理がない** | udp-echo の目的は「送ったものが返ってくるか確かめる」こと。まだ半分 |
| 9 | 🟡 | **`conn.Close()` がなくなった** | 2回目まではエラー確認の直後に `defer` があった |
| 10 | 🟢 | 長さのエラーだけ `Fprintf` で、**最後に改行がない** | ほかのエラーは `Fprintln`。そろえると、表示の後ろに次のプロンプトがくっつかない |
| 11 | 🟢 | ID のエラー文が「not a valid **type**」 | 種類のエラー文と同じ書き出しになっている。ID の範囲のエラーだと分かる文にする |

#4 を、自分側の住所と比べると、次のようになります。

```text
 自分側の住所（bind に使う）       ":9068"
   → 「自分のどのアドレスに届いても、9068番で受ける」
   → IPアドレスを省略してよい

 宛先の住所（送るときに使う）      ":9067"
   → 「どこの9067番に送るのか」が決まらない
   → IPアドレスが必要
       同じ Mac の Server へ   … 127.0.0.1
       Router VM の nc・Server へ … 10.0.0.1（README の C2）
```

> `0.0.0.0` が bind と宛先で意味が変わる理由や、宛先を `0.0.0.0` にしても届かないことは、[special-address-0000-qa.md](../qa/special-address-0000-qa.md) にまとめました。

#7 は、「**同じバイトでも、読み方で意味が変わる**」の実例です（[byte-sequence-and-interpretation-qa.md](../qa/byte-sequence-and-interpretation-qa.md) の2-3）。

```text
 buf[0] のバイト：01

   数として読む   → 1        ← 表示したいのはこちら
   文字として読む → 番号1の文字（目に見えない）  ← string(buf[0]) はこちら
```

数として表示するには、元の値（ポインタの先の種類・ID）を表示するか、`buf` を `% x` で16進表示します。

**動かした結果**

| 実験 | 期待 | 実際 |
|---|---|---|
| Mac で Server を起動し、`-kinds 1 -ID 1 -message hi` で送る | Server が受け取る | ❌ `write udp4 0.0.0.0:9068->:9067: sendto: no route to host`。その後も表示まで進んだ（#4・#6） |

| `-ID 4294967297` で送る | エラーで終了する | ❌ エラーの後に送信しようとした（#5） |
| 送ったものの表示 | 種類 1、ID 1、本文 hi | ❌ `kinds：` と `ID：` の後ろが目に見えない文字（#7）。本文の `hi` は正しく出た |

**→ M1（bind）完了。M2 は、送る形ができたところ**

### 4回目（現在）：宛先を引数で受け取って、送れるようになった

**コードの内容**

- `flag` で、宛先の IPアドレス（`-addr`、デフォルト `127.0.0.1`）とポート（`-port`、デフォルト `9067`）を、文字列で受け取る
- 2つを `":"` でつないで `ResolveUDPAddr` に渡し、宛先の住所を作る
- それ以外（引数のチェック、組み立て、送信、表示）は3回目と同じ

**途中で起きたコンパイルエラー**

最初は、引数の変数と、変換した住所の変数を、**どちらも `serverAddr`** という名前にしていました。

```text
 15行目  serverAddr := flag.String("addr", …)         ← *string として作られる
   ︙
 48行目  serverAddr, err := net.ResolveUDPAddr(…)     ← 同じ名前に *net.UDPAddr を入れようとする
 68行目  conn.WriteToUDP(buf, serverAddr)             ← *string のままなので渡せない
```

```text
./main.go:48:18: no new variables on left side of :=
./main.go:48:21: cannot use net.ResolveUDPAddr(...) (value of type *net.UDPAddr) as *string value in assignment
./main.go:68:32: cannot use serverAddr (variable of type *string) as *net.UDPAddr value in argument to conn.WriteToUDP
```

| エラー | 原因 |
|---|---|
| `no new variables on left side of :=` | `serverAddr` も `err` も**作り済み**なので、`:=` の左側に新しい変数がない |
| `cannot use … as *string value` | `:=` が「入れ直し」として扱われ、`*string` の変数に `*net.UDPAddr` を入れようとした |
| `cannot use serverAddr (variable of type *string)` | 68行目の `serverAddr` は `*string` のままなので、住所を受け取る `WriteToUDP` に渡せない |

Go では、1つの変数の型は**作ったときに決まり、後から変えられません**。引数の方の名前を `serverHost` に変えて、「引数で受け取った文字列」と「変換した住所」を**別の変数**にしたことで直りました。

| 中身 | 型 | 名前 |
|---|---|---|
| 引数で受け取った IPアドレスの文字列 | `*string` | `serverHost` |
| 引数で受け取ったポートの文字列 | `*string` | `serverPort` |
| `ResolveUDPAddr` で変換した住所 | `*net.UDPAddr` | `serverAddr` |

> 最初は `-port` のデフォルトが `"9068"`（Client 自身が bind しているポート）になっていました。引数を省略すると自分自身に送ってしまうので、Server の `"9067"` に直しました。

**直したこと**

| 直したこと | 前の回の問題 |
|---|---|
| ✅ 宛先の IPアドレスとポートを**引数で受け取り**、デフォルトを `127.0.0.1:9067` にした。Mac の Server に**届くようになった** | 3回目 #4 |

**できていたこと**

| できていたこと | 説明 |
|---|---|
| ✅ 名前で**中身の型**が分かる | `serverHost`（文字列）と `serverAddr`（住所）を分けたので、どちらを `WriteToUDP` に渡すか迷わない |
| ✅ 宛先を**引数で切り替えられる** | Mac では引数なし、VM では `-addr 10.0.0.1` のように使える。README の C6 の一部 |
| ✅ 変なポートは `ResolveUDPAddr` が**エラーにする** | `-port abc` で `lookup udp4/abc: unknown port`、終了コード 1 |

**まだできていないこと**（3回目からの続き）

| # | 重要度 | 問題 |
|---|---|---|
| 5 | 🔴 | 引数のチェックに引っかかっても、**終了しない** |
| 6 | 🔴 | 送信に失敗しても、**終了しない** |
| 7 | 🟡 | 種類と ID の表示が**文字化けする** |
| 8 | 🟡 | 返事を受け取る処理がない |
| 9 | 🟡 | `conn.Close()` がない |
| 10 | 🟢 | 長さのエラーだけ `Fprintf` で、最後に改行がない |
| 11 | 🟢 | ID のエラー文が「not a valid **type**」 |

> 補足：IPアドレスとポートを `":"` でつなぐ代わりに、`net.JoinHostPort` という関数もあります。IPv6 のアドレス（`:` を含む）でも正しくつないでくれます。今回は IPv4 だけなので、`+` でつなぐ書き方でも動きます。

**動かした結果**

| 実験 | 期待 | 実際 |
|---|---|---|
| Mac で Server を起動し、引数なしで `-kinds 1 -ID 1 -message hi` を送る | Server が受け取る | ✅ Server の表示（16進）に、送信元 `127.0.0.1:9068` と `01 00 00 00 01 68 69` が出た。終了コード 0 |
| `-port abc` で送る | エラーで終了する | ✅ `lookup udp4/abc: unknown port`、終了コード 1 |

**→ M2：送れるようになった。残りは、エラーの後の終了と、返事の受け取り**

## 4. 確かめるために使った実験

### 4-1. bind できない住所で起動して、エラー処理を確かめる

Server では「ポートの取り合い」でわざと失敗させました。Client は、Mac に `10.0.0.10` がないことを利用して、**何もしなくても失敗する**ので、そのまま確かめられます。

```text
 Mac のターミナル：
   Client を起動 > /dev/null   ← 標準出力を捨てて起動
   echo $?                    ← 終了コードを確認
```

| 確かめられること | 見るところ |
|---|---|
| エラーの中身を表示できているか | 空行ではなく、`listen udp4 ...` が出るか |
| エラーを標準エラー出力に出せているか | `> /dev/null` を付けても、エラーが画面に出るか |
| 終了コード | `echo $?` が 1 か |

> 自分側のIPアドレスの指定をやめた（ポートだけにした）場合は、Mac でも bind に成功するようになります。そのときは、Server と同じく、先に `nc -u -l 9068` で9068番を使っておくと、わざと失敗させられます。

### 4-2. 自分の Server に送って、届いたバイトを16進で見る

Server は受け取ったものを `string(buf[:n])` で表示するので、ミニフォーマットの種類と ID は目に見えない文字になります。**Server の標準出力をファイルに保存して、16進で見る**と、届いたバイトをそのまま確かめられます。

```text
 Mac のターミナル1：
   Server を起動し、標準出力をファイルに保存する（> server.out）

 Mac のターミナル2：
   Client を起動（-kinds 1 -ID 1 -message hi）
   echo $?                     ← 終了コードを確認

 ターミナル1の Server を止めてから：
   od -An -tx1 server.out      ← 保存した表示を16進で見る
```

| 確かめられること | 見るところ |
|---|---|
| 送信できたか | Client にエラーが出ないか。Server の表示に送信元（`127.0.0.1:9068`）が出るか |
| 組み立てが正しいか | 送信元の後ろに `01 00 00 00 01 68 69` が並ぶか |
| 範囲外の引数で終了するか | `-kinds 300` や `-ID 4294967297` で、送信まで進まず、`echo $?` が 1 になるか |

> Wireshark や tcpdump（Mac では `lo0`、`-X`）でも、同じバイトを見られます（[tcpdump-cheatsheet.md](../cheatsheets/tcpdump-cheatsheet.md)）。

## 5. この段階で学んだこと

| 学んだこと | 詳しい説明 |
|---|---|
| `fmt.Fprintln` は、**渡された中身を、渡された出口に書くだけ**。中身を渡さなければ、空行になる | [stdout-stderr-qa.md の 6-3](../qa/stdout-stderr-qa.md#6-3-q9-osstderr-と-fmtfprintln-はそれぞれ何をしているのか) |
| Server で身につけたエラー処理の形（`err` を標準エラー出力に出す → 終了コード 1）は、Client でもそのまま使える | [udp-echo-server-review.md](udp-echo-server-review.md) |
| Client は、ブロードキャストで送っても返事を受け取れるように、`DialUDP` ではなく `ListenUDP` を使う | [playground/README.md](../../../playground/README.md) の手がかり3 |
| エラーの中身（`can't assign requested address`）から、「そのIPアドレスはこのマシンにない」と読み取れる | このドキュメントの2回目 |
| 送る側は、OS が**読む**データがあればよい。入れ物を作るのは、決まった形に**組み立てる**とき | [go-send-buffer-and-copy-qa.md](../qa/go-send-buffer-and-copy-qa.md) の3章 |
| 組み立ては、1バイトは**直接代入**、複数バイトの整数は **`PutUint32`**、バイト列は **`copy`**。書く位置は**窓（切り出し方）**で決める | [go-send-buffer-and-copy-qa.md](../qa/go-send-buffer-and-copy-qa.md) の4・10章 |
| `int` は8バイト。大きい型から小さい型への変換は**切り捨て**で、範囲外の値は**エラーなしで壊れる**。だから変換の前に範囲を確かめる | [integer-size-and-byte-format-qa.md](../qa/integer-size-and-byte-format-qa.md) の7・9章 |
| `AppendUint32` は窓の**後ろに追記**する。窓の**中に**書くのは `PutUint32`。`buf[:5]` と `buf[5:]` は反対の範囲 | [byte-sequence-and-interpretation-qa.md](../qa/byte-sequence-and-interpretation-qa.md) の12章 |
| `:=` は左側に**新しい変数が1つ以上**必要。作り済みの `err` だけなら `=` | このドキュメントの3回目 |
| 宛先の住所には**IPアドレスが必要**。ポートだけで済むのは、bind する（自分側の）住所 | このドキュメントの3回目 #4 |
| 同じバイトでも、**数として読むか文字として読むか**で表示が変わる | [byte-sequence-and-interpretation-qa.md](../qa/byte-sequence-and-interpretation-qa.md) の2・3章 |
| 宛先に `0.0.0.0` は使えない。bind では「全部のアドレス」、宛先では「決まっていない」。Mac で試すなら `127.0.0.1` | [special-address-0000-qa.md](../qa/special-address-0000-qa.md) |
| 変数の型は**作ったときに決まり、後から変えられない**。同じ名前で別の型の値を入れようとするとコンパイルエラー。「引数の文字列」と「変換した住所」のように、**中身が違うものは別の名前**にする | このドキュメントの4回目 |

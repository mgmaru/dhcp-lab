# playground：本実装の前に試す実験コード

DHCPの本実装（`dhcp/`・`server/`・`client/`）に入る前に、必要な技術を小さなプログラムで試すためのフォルダです。

ここでの目的は、**きれいなコードを作ることではなく、しくみを手を動かして理解すること**です。

---

## 決まったこと（2026-10-15）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 実装言語 | **Go** | 標準ライブラリ（`net`）だけでUDPを扱える。Linux用のビルドをMacで作れる |
| 書き方 | **自分で一から書く** | 動かしながら理解するため |
| Claudeの役割 | **レビューだけ**。コードは示さない | 答えを見ずに、自分で考えて書くため。指摘とヒントだけを受け取る |
| モジュール | リポジトリの直下に `go.mod` を1つ置く（モジュール名：`github.com/mgmaru/dhcp-lab`） | あとで `dhcp/`・`server/`・`client/` と共通のコードを使い回せる |
| VMでの動かし方 | **Macで Linux 用にビルド**し、できたファイルを `scp` でVMにコピーして実行する | Client VMはインターネットに出られず、Goをインストールしにくい。Goのビルド結果は単体で動く |
| ポート番号 | STEP 1と同じ **9067番（Server）・9068番（Client）** | `sudo` が不要。既存のDHCPクライアントとぶつからない |

> トップの [README.md](../README.md) には「実装言語はまだ決めていない」と書いてあります。本実装の構成を決めるときに、あわせて更新します。

## 進め方

```text
 ① 要件を確認する（このREADME）
       ↓
 ② 自分でコードを書く
       ↓
 ③ Claudeにレビューを頼む（「レビューして」）
       ↓
 ④ 指摘とヒントをもとに、自分で直す（②〜④をくり返す）
       ↓
 ⑤ VMで動かし、tcpdumpで確認する
       ↓
 ⑥ 結果を docs/notes/results/ に記録する
```

### レビューの観点

レビューでは、**修正したコードは示しません**。何が問題で、なぜそうなるか、どう考えればよいかのヒントを伝えます。

| 観点 | 例 |
|---|---|
| 要件を満たしているか | 下の要件表（S1〜S4、C1〜C6） |
| 正しく動くか | 送信元ポート、ブロードキャストしたときに返事を受け取れるか、タイムアウト |
| エラー処理 | エラーを無視していないか、わかりやすいメッセージか |
| 後片付け | ソケットを閉じているか |
| Goらしい書き方 | 名前の付け方、パッケージの分け方 |

## udp-echo（STEP 1）

[learning-exercise.md](../docs/learning-exercise.md) のSTEP 1「UDP通信を理解する」を、**ツール（nc・socat）を使わずに、Goで実装**します。

ツールでの確認は完了しています（[step1-results.md](../docs/notes/results/step1-results.md)）。同じ動きを、自分のプログラムで再現するのが目標です。

### Server の要件

| # | 要件 | ツールでの対応 |
|---|---|---|
| S1 | UDPの **9067番** で待ち受ける（IPアドレスは何でもよい） | `nc -u -l 9067` |
| S2 | 受け取るたびに、**送信元のIP:ポート**とデータを表示する | — |
| S3 | **送信元に返事を送る**（受け取ったデータをそのまま返す＝エコー） | ncで `hi` と入力したこと |
| S4 | 1回で終わらず、**ずっと受け取り続ける**。複数のClientから来ても対応できる | nc は最初の相手としかやりとりできなかった |

### Client の要件

| # | 要件 | ツールでの対応 |
|---|---|---|
| C1 | **9068番に bind してから**送る | `nc -p 9068`、`socat bind=:9068` |
| C2 | **ユニキャスト**で送れる（宛先 `10.0.0.1:9067`） | 手順書の2 |
| C3 | **ブロードキャスト**で送れる（宛先 `255.255.255.255:9067`） | 手順書の3 |
| C4 | Serverからの返事を受け取り、**返事の送信元とデータ**を表示する | — |
| C5 | 返事が来なければ、**一定時間（例：3秒）であきらめる**（タイムアウト） | — |
| C6 | 宛先・送るデータ・ユニキャスト／ブロードキャストを、**コマンドラインの引数で切り替え**られる | — |

### 完了条件

tcpdumpで、ツールのときと**同じ結果**になれば完成です。

| 確認すること | 比べる記録 |
|---|---|
| ユニキャストで、行きと帰りの両方が記録される | [step1-results.md](../docs/notes/results/step1-results.md) の結果1 |
| ブロードキャストの送信元が `10.0.0.10.9068` になる | 結果3 |
| ブロードキャストの宛先MACが `ff:ff:ff:ff:ff:ff` になる | 結果3の4 |
| ClientがServerの返事を受け取って表示できる（ユニキャスト・ブロードキャストの両方） | **新しい確認項目**（ツールでは確認していない） |
| 返事が来ないとき、タイムアウトして終了する | **新しい確認項目** |

### 考えるときの手がかり

答えではなく、**調べるときの手がかり**です。

| # | テーマ | 手がかり |
|---|---|---|
| 1 | 使うパッケージ | 標準ライブラリの **`net`** パッケージ。`UDPAddr`・`UDPConn` という型と、`ListenUDP`・`DialUDP` という関数の違いを調べる |
| 2 | 送信元の取得 | `UDPConn` にはデータを読むメソッドが複数ある。**送信元のアドレスも一緒に返すもの**を選ぶ（`recvfrom` に当たるもの） |
| 3 | `DialUDP` と `ListenUDP` | `DialUDP` で作ったソケットは「**接続済み（connected）**」になり、決めた相手以外からのパケットを受け取らない。**ブロードキャストで送り、返事は `10.0.0.1` から来る**場合にどうなるか考える |
| 4 | bind | 送信元ポートを9068番にするには、どこで「自分側の住所」を指定すればよいか。[socket-bind-qa.md](../docs/notes/qa/socket-bind-qa.md) の流れ（socket → bind → sendto）と、Goの関数の引数を対応させる |
| 5 | `SO_BROADCAST` | Goの `net` パッケージは、UDPのソケットを作るときに `SO_BROADCAST` を**自動で有効にする**。そのため、結果4の `Permission denied` は、普通に書くと起きない。「Goが裏でやってくれていること」として理解しておく |
| 6 | タイムアウト | `UDPConn` に「読み込みの期限」を設定するメソッドがある。期限を過ぎたときのエラーの見分け方も調べる |
| 7 | 引数 | 標準ライブラリの **`flag`** パッケージ |
| 8 | 後片付け | 開いたソケットを、終了時に確実に閉じるGoらしい書き方 |

### VMでの動かし方

```text
 Mac で Linux 用にビルド ──scp──▶ Router VM（Server を実行）
                          └─scp─▶ Client VM（Client を実行。Router VM を踏み台にする）
```

| 手順 | 内容 |
|---|---|
| 1. ビルド | Macで、環境変数 `GOOS=linux`・`GOARCH=amd64` を指定してビルドする（クロスコンパイル） |
| 2. コピー | Router VMへは `scp`、Client VMへは `scp -J`（踏み台経由）でコピーする（[scp-qa.md](../docs/notes/qa/scp-qa.md)） |
| 3. 実行 | Router VMでServer、Client VMでClientを実行する。別のターミナルで tcpdump も動かす（[tcpdump-cheatsheet.md](../docs/notes/cheatsheets/tcpdump-cheatsheet.md)） |

> コピーしたファイルに実行権限（`x`）が付いていないと、`Permission denied` で実行できません。そのときは `chmod +x` を付けます（[file-vs-folder-permission-qa.md](../docs/notes/qa/file-vs-folder-permission-qa.md)）。
